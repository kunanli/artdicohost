# PRD — 功能需求与验收

## 人群与目的
- GGJ 现任/曾任 SO、RO：组织者交流、服务经历登记（不等同于表彰认定）。
- 潜在新站点：申请咨询、筹备成熟度了解，现场为**初步审核**而非自动核准。
- 行业讲者：演讲或圆桌讨论意向。
- 高校、教育机构、社区、工具及产业伙伴：展示、技术分享、资源合作及可能的赞助。
- 普通来宾：表达出席和感兴趣环节；统一排队审核。
- ARTDiCO 审核人员：核对、分组、内部备注、优先级、确认/候补。
- Maria / GGJ 指定代表：审阅适用的组织者与重点嘉宾候选信息；最终决定须人工确认。

## 公开页面
锚点：首页、活动介绍、活动亮点、活动日程（3 区响应式）、嘉宾（待公布占位）、展位、交通、意向登记、FAQ、隐私告知。顶部导航和底部按钮均跳到表单。移动端日程可切换 A/B/C 或水平滚动，保留时间栏。

## 表单流程
填写基础信息 → 选择多个身份 → 条件分支 → 参与形式和意向 → 一晚住宿申请 → 隐私同意 → 保存成功返回非连续编号 → 管理员收到待审记录。防重复提交，失败提示重试。申请的多个类别属于**同一条申请记录**。

## 审核流程
新提交 → ARTDiCO 核查 → 优先 / 考虑 / 需跟进 → 提交 Maria 审阅（适用者） → 已确认 / 待讨论 / 不邀请 → 发送正式通知（人工） → 活动后归档和删除计划。

## 可验收项目
- 手机及桌面可阅读全部内容；表单在微信内置浏览器可用。
- 所有必填项与分支条件正确，明确同意隐私告知才可提交。
- 写入私有 OSS 后才显示成功；断网、超时、重复提交均有明确处理。
- 未登录不能列出任何申请；后台按城市、类型、状态、住宿筛选及导出。
- 20 间客房仅供内部容量规划，对外不承诺；申请限一晚，住宿审核与参会审核分开。
- 不可从公开静态构建、浏览器源码、GitHub 或公开 OSS 读取个人数据。
- 一切「暂定」信息可在无需修改业务代码的配置文件中更新。

## 不在首版
线上付费、签到 QR、Apple Wallet、自动发房、完整 GGJ 年资奖项评定、规模化 CRM、用户自行登录门户、多语种（可预留结构）。
