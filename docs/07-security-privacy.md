# 安全与隐私发布清单

本文件为工程要求，不替代中国大陆个人信息合规法律审查。

- 公开表单前提供清晰、真实的处理者名称、联系方式、收集目的、字段类别、存储地区、保留期限、删除/查阅/更正方式、分享对象与适用法律要求。具体法律文本发布前需责任方核定。
- 申请审核信息涉及姓名、邮箱、微信、组织经历等。只按需要收集；不在第一阶段收身份证、护照、酒店订单、财务账单。
- 与 Maria 分享可能涉及个人信息跨境提供：先确认 Maria 所在地区、数据访问方式、必要性及依法适用的告知/同意与跨境合规要求；未经确认不要自动发送全量名单。
- 同意框默认不选，保留文案版本/时间。撤回、删除等申请要有人工处理入口和可执行操作记录。
- 明确数据库/私有桶的地区与保存期限；期限届满或目的完成后按适用要求删除或匿名化；不要无限期保留。
- 所有 OSS AccessKey、JWT/GitHub token 只能在 GitHub Actions secrets/受控环境中保存；独立最小权限 RAM；HTTPS；预防暴露。不得把实际 secrets 写进 `.env.example`。
- 管理后台要后端鉴权与最小权限、密码强哈希、登录限流、会话撤销、操作审计、防 CSRF/XSS、输入白名单、CSP；不要认为隐藏 admin 页面就是安全。
- 参考 IGDA 最新健康体检仍指出 Node 20 生命周期、依赖风险和非事务多对象写入问题；新站须重新审计版本，不能复述历史 CI 数字当作当前验证。
- 备份须加密和权限隔离；演练恢复；数据导出需留痕并限制访问；监控不能记录原始敏感表单内容。
- 上线前验证 OSS 公开桶不包含报名文件；隐私桶禁止匿名读取、禁止桶策略公开、服务端只授权必要前缀。
