# 后台保存方式

本轮统一所有可编辑后台表单，已随 PR #44／main `6984f8226cc7fa040a962500d29b63a5af3dc9eb` 发布；[准确 main 验收](admin-save-visibility-release-2026-10-22.md)、[新 session 入口](session-recovery.md)。

## 一条保存路径

修改当前表单后，底部的主要按钮是「保存」。旁边显示「未保存」；提交期间显示「保存中…」并锁定重复点击；核对服务器确实保存本次内容后，原位显示「已保存」。表单保留，继续修改就重新启用保存。没有「应用后再保存」步骤。

本机暂存只在刷新／中断后提供恢复，不显示成云端保存成功。常规暂存没有大块提示；发现旧内容、冲突或原请求待核对时才展示恢复工具。「已载入云端草稿」固定浮窗已移除，保存与结果留在表单附近。只读总览和个人汇总使用编辑链接，不提供无效保存。

公开发布另用「发布到前台」，会更新全部已保存活动内容。发信、审核批准名额、释放名额、下载邀请函都各有明确动作，不会由普通资料保存代替。活动内容的删除／补齐位置和公开开关直接完成对应云端保存，前台仍由明确发布更新。

## 错误与恢复

字段错误显示在对应表单或字段旁，填写内容保留。没有取得精确保存回执时，只显示「保存结果待核对」；不能将网络成功、普通刷新或本机暂存当成保存成功。原`operationId`、正文与`expectedRevision`保留，先核对原结果，再明确重试同一请求。多人修改冲突不会覆盖；一个表单保存也不会清空另一个未保存表单。

人员、志愿者、报名核查、名额设置、团队、受托登记、内容与设置分别核对自己的保存范围及回执。名额确认仍受共同300上限，资料保存不伪造本人同意或出席。退出清除本账号私人填写；未知云端结果仍如实提示。

## 微信群二维码

选择图片后，在到期时间附近选择有效快捷时间或填写准确时间。可选上限以服务端时间计算并显示为北京时间（UTC+8），最长七天；系统同时使用服务端和客户端校验。选「七天」会提供实际有效的准确时间，避免把七天后的23:59误当成七个24小时以内。

按「保存」上传并替换二维码。取得原图片摘要、到期时间和修订对应的有效回执后才显示已保存。校验失败保留选中的文件和时间，错误紧贴字段。旧二维码只在替换成功后失效；关闭入群图片是另一项明确操作。真实二维码、账号密码、报名和收件人不用于开发测试。

资源、备份与回退仍沿用[部署](08-deployment.md)和[完整备份](maintenance-backup.md)。旧未知请求和已保存未公开字段必须由兼容版本保留，不能用旧快照覆盖之后的业务。
