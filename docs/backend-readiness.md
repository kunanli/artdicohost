## 为什么现在不能在正式网站登录

- [公开站点准备脚本](../scripts/prepare-oss-site.mjs)用“云端工作人员后台尚未开放”提示替换两个管理页面，未发布登录脚本或私有图片。
- [FC 白名单](../scripts/prepare-fc-bootstrap.mjs)只打包六个启动验收文件，不包含本机内容 API；[FC handler](../functions/fc-api/handler.mjs)对管理与报名业务返回 503。
- 本机 API 仅绑定 `127.0.0.1` 并拒绝生产模式；本机会话和限流仅在单一进程内有效。不能直接把它上传 FC、代理上公网或把浏览器接到签名验收入口。
- GitHub Repository Secrets 用于自动部署，不会自动建立工作人员账号或邮箱。既有部署成功及三次签名健康检查只证明相应源码的启动验收通过。

邮箱作为登录标识与寄件邮箱是两项配置；填写 `@artdico.co` 不证明邮箱所有权、寄件域名核验或投递成功。账号密码与摘要只在受控服务端配置，不能写入公开页面或仓库，也无需在聊天提供。

## 建议的下一里程碑及验收

1. 接通本站独立的生产鉴权与私有储存，保留服务端角色、Origin / CSRF、最小权限及跨实例并发控制。正常部署沿用现有任务授权，不重新索取 AccessKey，不共用 IGDA 账号或资料。
2. 先开放工作人员内容后台：用隔离合成账号验证用户名和邮箱登录、错误密码拒绝、退出 / 撤销及角色限制；嘉宾照片、场次与展位保存后重启和重新登录仍存在。
3. 验证草稿不公开、明确发布后正式前台确实更新、撤回后资料与旧头像公共访问关闭，再补活动基本资料编辑表单。
4. 将本机已实现的工作人员学生登记／材料／分配／统计流程接通云端并实测，再实现学生自行申请和审核、正式报名与真实分类统计。用合成资料验证；不向生产环境提交真实报名。

云端备份、恢复与删除流程应随生产储存一起验收。当前本机文件恢复方式不能当作云端备份；群码原图、原有更换提醒和 Wallet / EmailJS 准备范围保持现状。
