# 默认公开与就近发布

本阶段按2026-10-22用户要求开发，准确验收与实际发布状态见[发布记录](admin-save-visibility-release-2026-10-22.md)。覆盖嘉宾、参与组织、游戏与作品、展位四类内容。

## 操作

每条记录旁与编辑窗口顶部都有「公开／未公开」开关。绿色「公开」是默认设置；只有手动关闭才设为未公开。照片、作品封面、资料确认、出席回复或现场安排不再阻挡公开，原有事实和授权记录分别保留，不因开关改变而冒称已确认或已授权。

各列表标题旁、页面底部保存栏都有「发布到前台」。列表开关直接保存到云端；编辑窗开关只改当前表单，须按「保存」才提交。尚未保存的本页填写会显示「保存并发布」，取得精确保存回执后再发布。发布会更新全部已保存活动内容，当前页面不限制发布范围。无发布权限的账号仍不能发布。

绿色设置不等于前台已经更新。旁边的中性标签显示「待发布／已发布／待更新／待撤下」。如保存或发布回执无法核对，保留原内容与请求，先核对原结果，不盲目重试。新规则部署本身不会发布真实草稿；工作人员核对记录并点击发布后，前台才变化。

手机嘉宾和展位列表以卡片显示，公开开关放在姓名或编号下方；组织和作品卡片直接显示开关。前台无照片显示姓名首字，无作品封面显示占位；待确认、婉拒、退出、取消等事实如实显示。负责人、联系方式、私人材料、内部备注始终不进入公开内容。

## 兼容与恢复

沿用schemaVersion1／storageVersion1，可选`visibility`仅接受`public`或`private`，缺省公开。旧记录的缺字段形状与历史正文保留；新旧客户端漏传字段时，两存储层按规范化稳定ID保留已保存的手动设置。恢复旧表单缺字段时，也保留当前已保存的未公开选择。开关不改授权事实；修改图片、姓名或关系不会自动关闭公开开关，但相关资料变更仍会清除当前表单的旧公开同意勾选，提示重新核对这份资料的授权。重核授权不阻挡默认公开或明确发布，旧授权历史保留。

实际发布快照冻结，读取或代码部署不会重新生成旧版。旧规则与新规则在同一修订可能有不同投影，发布前先按原CAS保存取得新修订，禁止改写同版公开字节。旧未知提交仍以原`expectedRevision`和原正文核对／重试。出席和共同300名额逻辑不变。

代码回退须使用理解可选`visibility`、保留明确未公开设置的兼容版本。不能回到忽略该字段的旧投影，也不能用旧完整快照覆盖新报名或内容。业务恢复与代码回退分开，遵循[完整备份](maintenance-backup.md)与[部署](08-deployment.md)。没有新增资源、权限、依赖或秘密配置。
