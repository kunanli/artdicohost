# 总览直接编辑与人员分配

现行操作以[统一保存](admin-save-workflow.md)、[默认公开](default-public-visibility.md)和[本轮验收／发布记录](admin-save-visibility-release-2026-10-22.md)为准；2026-10-20的先应用再保存步骤仅属历史，不再作为当前操作。

后台 `/admin/content/arrangements/` 的十五展位总览可直接打开展位侧栏，填写机构、项目、负责人、联系方式及简介，旧 `/admin/` 入口继续兼容。负责人和联系方式保留在私有内容中；公开投影继续移除这些字段。待确认展位允许保存，侧栏同时列出缺少的实际筹备资料。

展位修改直接按侧栏「保存」，核对精确云端回执才显示「已保存」，成功后保留编辑对象；没有先应用再保存步骤。列表公开开关直接保存，编辑窗开关随本表单保存，再明确「发布到前台」更新前台；未保存填写先「保存并发布」。关闭侧栏、切换位置或离页保护未保存输入；常规本机暂存不当作云端保存结果，已载入草稿固定浮窗移除。旧版草稿修订、同一展位已被修改、展位号或编号重复均拒绝覆盖，所有非本次编辑字段（包括内部备注）保留。

总览新增按时间排列的 A/B/C 区场次表。从展位卡或场次可选择人员，并同时核对其全部场次和展位分配。待保存内容不能用于人员分配。保存前读取最新内容修订，人员更新继续使用联系人 CAS 修订及服务端冲突校验。

关联报名者走意向报名分配 API；未关联联系人仅作私有筹备安排，不确认报名或改变真实回复。拒绝联系、婉拒参加者不能新增分配；已关联者由 API 核对有效确认名额。旧联系人更新入口也必须执行同一新增分配限制，不能绕过名额检查。移除历史分配仍允许。

人员保存不自动重试。提交结果不明或提交后刷新失败，界面锁定再次保存，要求先重新读取名单核对。退出登录会清除私有名单和未应用侧栏状态。

验证：五项纯逻辑回归覆盖保留其他字段、旧修订与占位冲突、缺项提示、拒绝/时间冲突、按实际区域去重的时间表。隔离 Chromium 流程使用合成人员验证两展位连续编辑、显式保存、时间表分配及退出清除；不向生产提交资料。
