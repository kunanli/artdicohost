# 前端本地开发

本阶段实现单页活动前端及本地交互预览。页面中的日期、嘉宾、署名、场地细节继续遵守原规范的待确认标记。表单只用于本地演示，不能接收真实报名，不生成正式受理编号；请仅填写合成资料。

按 [2026-10-18 产品更新](product-update-2026-10-18.md)，活动采用直接报名，不设置“先提交意向、等待邀请”作为普通参会门槛。现有 GGJ SO/RO 与新站点筹备身份可同时选择，随同一份活动报名收集；官方站点资格和年资核验独立进行。讲座及讲者仍待确认，并开放讲者招募与赞助商招募；演讲、赞助合作、展位及住宿申请分别处理，不影响普通活动报名。当前前端仍是明确标识的 mock，不因产品改为直接报名而声称已经受理真实申请。

## 本地环境

- Node.js：`24.19.0`，Node.js 24 LTS；这是本地与 CI 基线，不代表 FC 内置运行时。
- pnpm：`11.25.0`，与根目录 `package.json` 的 `packageManager` 保持一致。
- 安装依赖需要可用的 npm registry 网络；离线环境不能把未完成安装记作验证通过。

依赖锁文件已从通过的 [CI 运行 39113786450](https://github.com/kunanli/artdicohost/actions/runs/39113786450) 恢复并核对；标准安装使用 `--frozen-lockfile`。当前本地环境无法访问 registry，本地安装和构建仍未验证；已完成的类型检查、15 项测试、构建和全量依赖审计来自该次 GitHub CI。此次恢复冻结安装并增加源码边界检查后的最终运行尚待完成，以对应 PR 最新检查为准。

在仓库根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm dev --host 127.0.0.1
```

使用终端打印的本地地址。无需阿里云账号、云端环境变量或真实个人资料；`.env.example` 的 `PUBLIC_API_BASE` 是未来接口对接的预留名称，应保持空值。当前演示不因填写该值而开启真实报名。

本地检查与静态预览：

```sh
pnpm check:source
pnpm check
pnpm test
pnpm build
pnpm preview --host 127.0.0.1
pnpm audit --audit-level=moderate
```

`preview` 需要先成功构建 `dist/`。成功构建、依赖审计、浏览器交互和真机测试是不同的验证项，分别记录在 [前端验证记录](frontend-validation.md)；当前状态以该记录和实际命令输出为准。

## 配置和资料边界

公开文案及确认状态在 `src/config/` 管理，页面和组件在 `src/`。修订活动事实时保留来源与确认状态，未获得授权的嘉宾照片、地图链接及合作署名不作为确定内容发布。原开发规范及 [实施计划](implementation-plan.md) 保留历史基线；普通参会报名采用上述最新产品口径，云端接入和安全门槛继续适用。

表单内的演示结果不等于真实报名受理、演讲安排、赞助合作确认或住宿批准。当前阶段不向 API 或 OSS 发送报名，不把填写内容写入 GitHub、公开对象或长期浏览器存储。报名后端校验、幂等、防覆盖、分布式限流、生产管理员鉴权及资料生命周期在后续阶段实现和验证。

工作人员可通过 [本地内容后台](local-content-backend.md) 登录、安排场次和展位、保存草稿并单独发布。它使用独立的本地 scrypt 账号、cookie / CSRF 和原子 JSON 文件，启动命令为 `pnpm admin:local`；不连接云端、不接收报名资料。`pnpm dev` / `pnpm preview` 只提供前端，不能替代此本地 API 服务。

任何 `PUBLIC_` 变量均按可被浏览器读取处理，只允许公开配置。RAM AccessKey、GitHub token、会话密钥和报名资料不得进入前端环境文件、源代码、构建产物或日志。真实环境文件已被忽略，`.env.example` 只保留空值及说明。

## PR 检查和发布边界

[Frontend checks](../.github/workflows/check.yml) 在 PR、`main` 推送或手动触发时，以 Node.js `24.19.0` 和 pnpm `11.25.0` 执行冻结安装、源码边界检查、Astro 检查、测试、构建和全部依赖审计（含构建工具）。任务只有 `contents: read` 权限，不持久保存 checkout 凭据，不使用云端 secrets，也没有发布步骤；Action 版本固定至已核对的提交。`frontend-check-output` artifact 仅保留 `package.json`、`pnpm-lock.yaml`、`dist/` 三类文件，期限 3 天。检查失败时修复或明确记录阻塞项，artifact 存在不代表检查通过。

本地前端回退通过切换到先前已验证的代码提交并重建完成，不涉及用户资料。云端初始化、staging/production 部署与回滚、私有数据备份及删除操作尚未实现，后续按实施计划 P4–P7 编写操作步骤并验证；本文件不是生产运行手册。

FC 仍须独立完成账号/地域和自定义运行时预检；OSS 仍须完成私有权限、从未启用版本控制的数据桶、防覆盖、跨实例并发及恢复验证。生产发布、购买云资源和 DNS 修改继续遵守原授权门槛，本次前端工作不会触发这些操作。
