## 4. 存储、并发与失败恢复

保留 `registrations/{eventId}/{uuid}.json`、私有账户、审核及审计分离的原则。补充幂等对象和审核修订空间；所有 schema 带版本，索引和汇总可从权威记录重建。公开站点桶只含构建产物及授权公开素材。

### 4.1 必须先证明的 OSS 能力

官方 `PutObject` 的 `x-oss-forbid-overwrite=true` 支持同名创建冲突，但在 versioning 为 Enabled 或 Suspended 时无效；当前文档不足以支持“普通 PUT + If-Match 就是更新 CAS”的假定。[PutObject](https://www.alibabacloud.com/help/en/oss/developer-reference/putobject)

因此拟采用独立、从未启用版本控制的数据桶，并预检防覆盖行为；加密备份放在另一受限资源中。不得为了备份在权威写入桶开启或暂停 versioning。P4 先在隔离 staging 资源用两个独立服务实例证明同名创建只有一个成功；不通过则阻止真实写入发布，评审另一已验证的协调机制或事务存储，不能用单进程锁冒充分布式保护。

### 4.2 提交和重试协议

1. 客户端为一次提交使用不可预测的幂等键，并取得服务端签名、限定事件与有效期的提交令牌；API 对规范化业务内容求摘要，以服务端 HMAC 后的键定位私有幂等对象。过期令牌不得创建新报名，令牌签发接口及有效期在 P4 契约明确。
2. 条件创建幂等记录，固定报名 UUID、查询编号、请求摘要和时间。相同键与相同内容重用该身份；相同键而不同内容返回冲突。
3. 条件创建报名权威对象；只有确认该对象已成功写入且内容对应本次申请后，才返回正式受理成功和非连续查询编号。编号不作为公开读取个人资料的凭证。
4. 并发或响应丢失时读取已有幂等/报名对象：同键同摘要且已有成功报名，即使活动已截止也返回原受理结果；已撤回/删除则返回对应状态，不重新建档。只有预留幂等对象、报名尚未落库时，才在重新验证开放/截止、令牌及隐私规则后补写同一 UUID，不制造第二条报名。
5. 初始审核和审计投影失败时标记可恢复工作；报名列表以权威报名对象为准，将无审核投影的记录呈现为 `new`，避免报名被静默漏掉。定期对账、幂等补偿并告警，不能声称多个 OSS 对象具有事务。

### 4.3 审核修订与审计

拟将 [06-architecture-data](06-architecture-data.md) 的推荐单文件审核路径细化为 `reviews/{eventId}/{uuid}/revisions/{version}.json`，每次包含完整审核状态、预期前版本、操作 ID、操作者和不含原始联系资料的审计元数据。服务端验证预期前版本为当前已接受的最大连续版本，版本按数字解析；两名审核员基于同一版本只能竞争创建同一个下一版本对象。条件创建失败返回 409，刷新后由操作者决定，不覆盖先前修改。

权威修订写入与审计元数据在同一对象内完成，外部 `audit/` 对象及索引是可重建投影；记录待补偿任务并验证故障恢复。审核结果读取已接受修订，不能信任未经验证的可变“最新版本”缓存。更正、撤回、账户/公开配置修改也需要明确并发策略；删除流程须覆盖历史修订，不以“不可变”代替个人资料删除。

状态分别保存：候选 `new/in_review/awaiting_maria/approved/discussion/not_this_time/withdrawn`；住宿 `not_requested/requested/pending/approved/declined`；推荐 `priority/consider/follow_up`；Maria 反馈和正式邀请状态独立。服务年资表彰、站点资格、席位及住宿由人工确认。首版配额修改串行由指定负责人操作，避免把跨申请房间总量当作单条修订就能原子保证。

### 4.4 列表、权限与公共边界

- 列表、筛选、导出循环处理 OSS `IsTruncated` 与 `NextContinuationToken`；API 使用受控游标及事件授权，不能只读取前 1000 条。量大后再评估可重建索引和数据库。[ListObjectsV2](https://www.alibabacloud.com/help/en/oss/developer-reference/listobjectsv2)
- API 侧执行事件范围和角色授权；私有响应 `Cache-Control: no-store`，不进入 CDN；错误不含对象键、堆栈或秘密。
- 限流必须覆盖多 FC 实例；P4 评估平台网关限流或经过并发验证的共享计数机制，未完成则不开公众提交。额外服务及预算须在配置前确认。
- FC 优先使用运行角色的临时凭据；部署身份、备份身份和运行身份分开。浏览器只读取 `PUBLIC_API_BASE` 等公开配置，不能获得 AccessKey、会话签名密钥或 GitHub token。

## 5. 后台、导出与生命周期

`/admin/` 使用独立账号。用户以不可重复的稳定 ID 标识，登录名唯一性由服务端校验；密码强哈希，登录限流，会话可撤销，采用 Secure/HttpOnly cookie、明确 CORS/Origin/CSRF 校验。所有管理路由在 API 执行授权，隐藏页面不能代替权限。

| 角色 | 默认授权 |
| --- | --- |
| superadmin | 账户管理、全部授权事件资料、导出及删除处理 |
| reviewer | 只读/审核获授权事件；导出须有单独许可 |
| editor | 编辑公开内容草稿；不能读取报名资料 |
| Maria | 不自动创建账号；指定管理员通过受控流程发送最小必要资料 |

后台支持姓名、机构、城市、类型、时间搜索，及参与方式、住宿、出席意向、审核状态筛选；详情展示原始资料与内部备注，支持负责人、站点核验、候选角色、联系日期、下一步、Maria 日期/反馈和正式邀请状态。现场席位、展位和每晚住宿分别计量，住宿一人一晚。

保留规范中的 8 类示例 API，并补充独立契约：登出/会话撤销、用户与事件权限管理、公开内容草稿及发布、资料更正、撤回和删除任务。草稿/发布接口仅允许白名单公开字段；报名详情中的内部字段不得混入 `GET /api/public/event`。具体路径、状态机、错误码及角色矩阵在 P1/P4/P5 分阶段写入 API 文档。

CSV 和 Excel 导出先通过事件授权、字段白名单及用途检查，在服务端生成；下载经过会话复核、短时有效并审计，默认不生成公开 OSS 链接。处理公式注入、转义与中文兼容；不导出原始数据库。向 Maria 传递前确认地区、必要字段、授权范围及适用的隐私审核，系统不自动发送。

保留期限、处理者/联系方式、存储地区及撤回渠道明确后才能开放真实表单。更正与删除申请由受控管理员核验；撤回/删除先建立最小必要的私有处置标记，令旧键和未完成补写失效，再通过与提交/审核共用且经并发验证的协调协议阻止新修改、等待在途操作结束，执行可重试清除任务。协调与残留检查未完成不得宣称删除完成。

清除范围包括报名、审核修订、幂等映射、导出副本及约定的备份到期处理。处置标记只保留阻止重放/恢复所需的引用、状态和时间，仍按隐私数据限制访问与保留期限，不能称为匿名审计；至少覆盖未失效令牌及备份恢复窗口，到期处置规则须人工核定。服务端拒绝以过期令牌重建资料，恢复备份后先重新应用删除记录再开放访问，避免复活已删除资料。一般运行日志不写个人资料。
