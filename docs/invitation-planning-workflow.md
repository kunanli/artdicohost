# 邀约名单、人员与活动安排

第一版由后台生成 PNG，工作人员自行在微信发出。没有程序发送、送达证明或匿名个人邀请链接，Wallet／邮件仍仅准备。真实工作簿通过既有导入器保存在主工作区的忽略目录；开发和测试使用独立合成资料，不将真实名单提交 Git、放进 dist 或用作夹具。

## 实际操作

1. 在「人员与邀约」手动新增，或在本机预览并导入意向名单。手动新增的联络同意默认未知，工作人员核实后才可明确选择同意；有邮箱或微信不等于同意。
2. 修正姓名、邀请称呼、机构、职位、城市及联系方式。来源身份、原始摘要与历史选项不变，首次修正保留服务器创建的编辑前快照及其摘要。同一原问卷再次导入不会覆盖修正、跟进或邀请记录；来源本身变更仍须核对。
3. 标记负责同事、优先级、下次跟进、实际出席回复、多选参与形式（嘉宾、演讲、圆桌、主持、攤位、学生展示或参会）、参与场次与展位。列表显示已安排的时间／区域／展位及失效引用，可按参与形式筛选未安排对象。历史预计到场不自动变成确认出席。
4. 对已同意联络者预览、下载 PNG；生成版本单独记录。确实由工作人员在微信发出后，再保存「已发出」。重新生成不代表新版已经发出，对方回复也不由图片生成或下载推断。
5. 已同意联络且未婉拒者可由兼具 `outreach` 与 `editor` 的工作人员「管理嘉宾资料」。跨页只带内部 ID，重新授权后取得姓名、机构、GGJ 职务与内部关联 ID；同一对象重新打开已关联的嘉宾资料，避免重复新增。新嘉宾仍待确认、没有头像、公开同意为否。工作人员另行核实实际答复、上传获授权照片、保存及发布，不自动保存、不改变名单状态、不把联系方式复制到嘉宾。名单回复与嘉宾公开确认分别维护，修改其一不代表另一项自动同步。
6. 在活动／嘉宾编辑器调整场次、时段、区域、讲者与展位，保存草稿再明确发布。内部人员安排不会自动变成公开讲者或已获展位。

名单与内容有独立修订号；冲突或未知保存结果须重新读取核对，不自动重送。退出清除名单、表单及邀请预览，离开／取消须保护未保存修改。关联只使用稳定内部 ID，不自动合并同名嘉宾，不假称跨两个日志有原子事务。

## 学生展示

活动编辑器的「学生展示」独立维护作品名、团队展示名、学校、负责人、邮箱／微信、团队人数、答复状态，以及展位试玩／上台分享的选择和分配。材料首版用最多十个 HTTPS 链接记录，链接及内部备注仅供工作人员，不自动下载或公开。作品封面另行上传至受控图片存储，支持静态 JPEG／PNG／WebP（512 KiB、2048×2048 上限），不会把材料链接当成公开图片。

统计显示已确认参加的团队数及这些团队填报人数、有效展位／分享分配数与符合公开门槛数；不是正式报名、去重人员或实际签到。只标记意愿并不自动获得展位或场次。

保存草稿后，只有展示状态已确认、实际回复参加、明确作品公开授权、有有效封面及至少一项对应有效安排的作品才能进入明确发布的前台快照。公开仅输出作品／团队名、简介、图片和有效安排，不含学校、私人负责人、邮箱／微信、人数、材料或内部备注。授权撤回、删除或安排撤销后须保存并重新发布；当前发布版不再引用的图片随即不能通过公开接口读取。旧客户端缺少整个展示数组时不得清空已有记录，过期修订拒绝保存。

## 现场配置总览

「现场配置总览」将十五个位置、A 区演讲／分享、B 区工作坊／交流及明确标记为工作坊的场次集中核对。展位编辑器保留原编号，另选择 1–15 号位置；未指定位置的历史记录单独列出，不凭编号或名称自动占位。待确认和已确认均预留位置，取消不占位；同一有效位置不能重复分配。空位只表示尚未安排，不代表已收到申请或承诺参展。

场次形式由工作人员明确选择。未知活动保留待分类，不按标题猜测工作坊；种子只标记原安排已经明确的演讲、圆桌和学生分享。每项列出时段、嘉宾、名单参与对象及学生团队，保留真实回复／嘉宾确认状态和失效安排提示。名单参与形式是全活动记录，不能因此宣称该人在每个关联场次都担任同一官方职务。

总览只读已保存内容，显示内容及名单两个独立修订号，不承诺跨日志原子一致；本页尚未保存的编辑不直接算成最新安排。联系人与同一关联嘉宾使用稳定人员身份去重，学生团队与填报人数独立统计，不能混为去重报名或签到。总览要求同时具备 `editor` 与 `outreach`；只有其中一种权限时不读取名单。接口不输出邮箱／微信、问卷、材料链接、同意历史、来源摘要或内部备注。

旧客户端保存现有记录时省略新形式／位置字段，会保留已存标记；明确选择待分类或未指定位置才会清除。公开发布仍是独立操作，总览不是前台内容、出席证明或实际报名统计。

## 权限与新增 API

所有写入保留准确 Origin、会话、CSRF 及服务端角色。`outreach` 可读最小排程，不因此取得完整内容草稿内部备注或发布权限。

| 接口 | 用途 |
| --- | --- |
| `POST /api/admin/contacts` | outreach；`{expectedRevision,profile}`，身份及来源由服务器创建 |
| `PUT /api/admin/contacts/:id/profile` | outreach；`{expectedRevision,profile}`，只修正允许的基本资料 |
| `GET /api/admin/planning` | outreach；最小场次／展位及功能标记，不含嘉宾私人资料或内部备注 |
| `GET /api/admin/arrangements` | editor + outreach；十五个位置及场次的人員最小总览、独立修订和筹备统计，只读已保存数据 |
| `GET /api/admin/contacts/:id/guest-prefill` | outreach + editor；核实联络同意且未婉拒后返回三栏与关联 ID／回复状态，不写入 |

原有读取、跟进、邀请生成／人工发出契约见[私密名单](local-contacts.md)。功能标记 `contactImport:false` 时关闭 Excel 导入，本机 Map 预览令牌没有被当作生产共享服务。生成、人工发出、确认出席与公开授权互相独立。

## 云端准备及待办

独立 `cms/v1/contacts` 日志复用 OSS 位置条件追加；单状态 1 MiB、审计 1000 条，达到容量拒绝写入。会话、名单及邀请记录须有共享持久化确认，损坏或未知 ACK 关闭操作，不回退到文件或内存。审计仅含必要元数据，不把姓名、邮箱或邀请称呼写进公开日志。

`PUBLIC_CONTENT_API_ORIGIN` 默认空白，只接受准确的 `https://api.artdico.host`。未来主站匿名读取 `/api/public/content`，头像也来自同一受控 API，不携带管理凭据；本机同源读取保留。其他来源、管理／报名路径与 URL 变体均不作为公开读取配置。

**云端业务仍未开放。** 新模块不在现行六文件启动包，主站未启用跨源读取。还须完成专用角色、账号、API HTTPS／精确路由、生产后台包、容量维护／备份／恢复／删除及合成端到端验收，见[云端操作单](cloud-content-setup.md)。本机入库不等于官网后台可登录或云端同步；真实资料迁移按当时授权与就绪结果处理。
