## 先验收这些流程

| 入口 | 操作与预期 |
| --- | --- |
| 活动与内容 | 修改一个真实区块，等「已暂存本机」后刷新；明确恢复填写，核对后按附近「保存到云端」。套用、云端保存和公开发布分开；已上传图片引用可恢复，原图文件须重新选择。 |
| 人员与邀约 | 原始资料保留，分别调整回复、负责人、跟进日期和职责；确认参加后核对共同名额。旧已答应者先预览再明确同步，不按姓名／邮箱另造人。个人工作页串联报名、嘉宾、组织、场次、展位和志愿分工。 |
| 嘉宾与组织 | 按稳定 ID 关联既有人物，组织选择明确成员。公开资料与肖像须重新授权；停止公开、保存并发布后才可为已公开嘉宾换人。一般参加组织不自动占展位。 |
| 公开申请 | 学生在身份选择；姓名、邮箱、身份和隐私同意为主要必填，机构／城市／微信选填，主题提案独立展开。提交是待审核，不是获邀；后台核准后有位确认并走确认信，满额候补。 |
| 300 人名额 | 所有参会与工作人员共用 300，不因多个角色或团队关系重复计数。候补、拒绝、撤回及待审核不算已确认；分配与审核分别保存。 |
| 志愿者与分工 | 选择既有人，填沟通与服务时间，建立岗位／班次后安排；人数与人次分列，冲突由后端拒绝，取消保留历史。 |
| 暂存与未知回执 | 刷新后明确恢复，不自动云端提交／发布／寄信；首次明确拒绝保留填写。结果未知只核对原请求，不能换键盲建。云端版本不同只查看旧填写。 |
| 邀请函 | 人员与邀约打开邀请函，按「使用本次活动信息准备新版」，核对姓名、日期、时段及地点后预览／保存／下载；旧派发历史保留。已核准且有名额的公开申请人在私人确认页按「生成个人邀请函 PNG」，核对完成后可下载或手机长按。生成图片不会发信或标记已派发。 |
| 用户管理 | 现有管理员登录[用户管理](https://api.artdico.host/admin/settings/#staff-accounts-title)，分别按「准备 zhouyufei」「准备 wangying」自动生成独立初始密码；按「保存工作人员账号」，取得有效回执后从「本页已确认保存的登录资料」私下交付。**两个正式账号尚未建立**，密码不进缓存／Git／链接，离页后清除。 |
| 权限 | 两个协作者使用 editor／publisher／outreach／reviewer 完整组合，可日常编辑、发布、人员安排、审核、Excel 与通知。只有管理员可管理账号及系统备份／恢复；停用立即撤销旧会话。 |
| Excel | 人员及报名各自导出当前保存资料；联络、完整原回答、安排另选。Excel 用实际软件打开核对中文、前导零和状态；导出不代替完整备份。 |

本机保存有短暂写入时间，事务完成才显示已保存；尚未完成离页会提醒。突然终止进程不能保证最后一个字落盘。普通草稿七天有效，未知提交不会因此失去原键。明确退出清除本账号本机草稿，跨页签同步；退出请求失败会说明云端会话尚未确认结束。

## 业务资料与邮件

真实名单、照片、群码和联络进度以私密后台为准，本开发只用合成资料，不重复导入或替真实人安排。原问卷 39 行的授权／来源继续保留；代登记不冒充本人隐私同意，也不自动群发。用户已确认 EmailJS 正常，保留现有 LoginPlan／template_89mgpj9 及受控密钥，不为验收重新设置或实寄。

只有已确认的合资格公开申请会走确认通知。服务商接受不等于本人收件；unknown 不重送。工作人員手动邀请的生成／下载／实际派发记录分开，旧邮件不会因为新版海报而补寄。群二维码需工作人员上传真实图片与有效期。
