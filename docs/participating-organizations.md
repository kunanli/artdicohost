# 参与组织名录

本轮操作按[默认公开](default-public-visibility.md)与[统一保存](admin-save-workflow.md)更新，准确来源及实际部署状态见[本轮验收／发布记录](admin-save-visibility-release-2026-10-22.md)。旧版「先应用、再保存」及「确认且获授权才公开」规则已被本轮操作替代；历史发布证据不作为当前操作步骤。

活动后台独立维护参与组织的图片、名称、对方页面链接及参与形式，包含参展和一般参与；组织不必先取得展位才能列入。参与形式、确认与授权事实、公开设置及实际发布进度分别维护，新增组织不改变十五个展位、个人报名或 300 人名额。

## 后台操作

在活动后台的参与组织区域新增或编辑组织。名称必填；组织图片及外部页面链接可留空，没有图片时前台用名称呈现，没有链接时不生成可点击的空链接。参与形式可选「参展」「一般参与」或「参与形式待确定」，不根据组织名称猜测身份。展位位置、项目、负责人及联络资料继续在原有展位模块安排。

旧草稿或旧公开快照缺少组织字段时，沿用原有四个名称的兼容显示；读取旧资料不写入、自动确认新的组织或编造 logo／网址。在组织表单直接按「保存」，本次云端回执核对成功后原位显示「已保存」，保留当前编辑对象，不再先应用再保存。按「发布到前台」才更新全部已保存活动内容；部署或读取不会重生成旧公开快照。

组织图片可用[本地图片编辑器](staff-image-editing.md)裁切、缩放、移动、取色去背或画笔修整，透明结果保留 PNG；真实图片预览取消人工灰底与内距，按自然比例贴合。复用后台已有的私有内容定址图片上传；浏览器自动调整方向、缩小并重新编码，移除原始元数据，最终不超过 512 KiB。页面保留比例呈现组织图片，不使用人物头像的圆形裁切。只有实际已保存且可验证的图片可以用于组织；没有成功上传回执时不显示上传成功。图片、名称、链接或参与形式改变仍会清除当前表单的旧公开同意勾选，提示重新核实这份资料的授权；旧历史保留，不自动更改公开开关，也不阻挡公开或替工作人员授予真实授权。

组织默认绿色「公开」；明确切为「未公开」使用 `visibility:'private'`，保留参加确认状态、公开授权事实、组织名称、图片、链接及内部备注。列表开关直接保存，编辑窗开关随本表单「保存」提交。「已退出」另行维护实际参与状态，不代替公开开关。取得保存回执后仍须明确发布才从前台撤下；中性标签显示「待发布／已发布／待更新／待撤下」。明确发布空名单或撤下全部组织后，不再显示网站原有四个名称；API 读取失败也不会重新显示旧名单。修订冲突保留输入并先核对，不能覆盖其他工作人员的保存结果。

## 数据与公开边界

内容根字段 `organizations` 为可选数组，最多 200 条，顺序即呈现顺序。每条记录有以下字段：

| 字段 | 约束 |
| --- | --- |
| `id` | 本活动唯一稳定 ID，1–80 位字母、数字、短横线或下划线，不能和场次／嘉宾／展位／作品 ID 重复。 |
| `name` | 必填单行名称，最多 160 字。 |
| `logoId` | 空字串或后台生成的内容 SHA-256 加 `.jpg`／`.png`／`.webp`；不接受外部图片 URL、路径或伪造格式。 |
| `website` | 空字串或最多 500 字、不含帐号／密码及空白控制字元的 HTTP／HTTPS 对方页面链接。服务端不抓取该页面。 |
| `participation` | `undecided`、`exhibitor`、`attendee`，不自动占用展位。 |
| `status` | `pending`、`confirmed`、`withdrawn`。 |
| `publicConsent` | 明确的 boolean，保留真实授权事实；不再作为公开门槛，也不因公开开关改写。 |
| `visibility` | 可选 `public`／`private`，缺省公开；只有明确 `private` 才排除新发布内容。 |
| `internalNotes` | 可选私有备注，最多 4000 字，不公开。 |

旧草稿和公开快照缺少 `organizations` 时不补空字段，保持历史内容形状与 hash。旧客户端保存完整旧内容、但遗漏新组织数组时，两个内容 store 都保留当前服务器已有组织；显式 `[]` 才是清空名录的请求。按规范化稳定 ID 编辑时，旧客户端漏传 `visibility` 会保留当前已保存的手动设置；遗漏私有备注也保留原值，明确 `internalNotes:''` 才清空。非数组、缺少必要字段或无效状态仍拒绝，不将缺失或 false 的授权事实补成 true。

公开条目只输出白名单 `id`、`name`、`participation`、`website`、`logoUrl`、`logoId`、原 `status`／`publicConsent` 及存在时的 `visibility`；不将真实状态改成 confirmed 或授权改成 true。`logoUrl` 只由后台图片 ID 产生固定 `/api/public/portraits/<id>`；输入若包含此衍生字段，必须准确匹配，不能指定任意外部图片。内部备注和其他私有资料不进入公开内容。旧公开快照保持原字节；旧同版投影需先保存新修订再明确发布，两种 store 重启后仍可验证及重读历史快照。

所有非空 logo 引用，包括未公开草稿，都在保存及发布前验证实际图片。匿名图片读取仅允许当前公开快照仍引用的组织图片；撤回或发布新名单后，不再凭旧引用读取。前台外链使用安全新窗口及不传 referrer，跨源图片读取不携带工作人员 Cookie。链接点击与实际参展／出席记录分别处理。

## 备份、恢复与回退

现有内容 journal、审计、权限、Origin／CSRF 和修订冲突机制继续适用，没有新增服务、IAM、DNS、trigger、环境变量或依赖。完整加密备份会沿每份历史草稿的 `logoId` 及历史公开 `logoUrl` 收齐组织图片；缺图或无效引用使备份失败，不静默遗漏。隔离恢复保留历史对象及图片，不激活旧名单、不恢复会话。

已有组织写入后，使用理解可选 `visibility` 并保留明确未公开设置的兼容版本修复。需要回退时先暂停编辑／发布、保存完整加密备份，再核对当前公开状态；不要用忽略该字段的旧投影或旧版本重写整份内容，也不要用旧快照覆盖新资料。代码发布或读取旧快照不会替工作人员确认真实组织及授权。
