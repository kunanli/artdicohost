# 参与组织名录

2026-10-21。活动后台独立维护参与组织的图片、名称、对方页面链接及参与形式，包含参展和一般参与；组织不必先取得展位才能列入。参与形式与确认／公开状态分别维护，新增组织不改变十五个展位、个人报名或 300 人名额。

## 后台操作

在活动后台的参与组织区域新增或编辑组织。名称必填；组织图片及外部页面链接可留空，没有图片时前台用名称呈现，没有链接时不生成可点击的空链接。参与形式可选「参展」「一般参与」或「参与形式待确定」，不根据组织名称猜测身份。展位位置、项目、负责人及联络资料继续在原有展位模块安排。

网站原有四个组织名称是已确认的公开事实；旧草稿还没有组织字段时，前台保留这些名称，后台可从这份原有名单开始编辑。首次明确应用组织编辑后，完整名录才加入工作草稿；读取旧资料不会写入、自动确认新的组织或编造 logo／网址。应用编辑、保存草稿和发布分别执行，只有保存并发布后的确认及授权资料会改变网站。

组织图片复用后台已有的私有内容定址图片上传；浏览器自动调整方向、缩小并重新编码，移除原始元数据，最终不超过 512 KiB。页面保留比例呈现组织图片，不使用人物头像的圆形裁切。只有实际已保存且可验证的图片可以应用到组织；没有成功上传回执时不显示上传成功。图片、名称、链接或参与形式改变后，重新核对所需公开授权。

停止公开改变状态／授权，保留组织名称、图片、链接及内部备注，仍可继续编辑或以后恢复公开。明确发布空名单或撤回全部组织后，不再显示网站原有四个名称。未发布的草稿调整不会改变当前公开名单；修订冲突需先读取新版本后核对，不能覆盖其他工作人员的保存结果。

## 数据与公开边界

内容根字段 `organizations` 为可选数组，最多 200 条，顺序即呈现顺序。每条记录有以下字段：

| 字段 | 约束 |
| --- | --- |
| `id` | 本活动唯一稳定 ID，1–80 位字母、数字、短横线或下划线，不能和场次／嘉宾／展位／作品 ID 重复。 |
| `name` | 必填单行名称，最多 160 字。 |
| `logoId` | 空字串或后台生成的内容 SHA-256 加 `.jpg`／`.png`／`.webp`；不接受外部图片 URL、路径或伪造格式。 |
| `website` | 空字串或最多 500 字、不含帐号／密码及空白控制字元的 HTTP／HTTPS 对方页面链接。服务端不抓取该页面。 |
| `participation` | `undecided`、`exhibitor`、`attendee`，不自动占用展位。 |
| `status` | `pending`、`confirmed`、`withdrawn`。 |
| `publicConsent` | 明确的 boolean；只有 true 且 status 为 confirmed 才公开。 |
| `internalNotes` | 可选私有备注，最多 4000 字，不公开。 |

旧草稿和公开快照缺少 `organizations` 时不补空字段，保持历史内容形状与 hash。旧客户端保存完整旧内容、但遗漏新组织数组时，两个内容 store 都保留当前服务器已有组织；显式 `[]` 才是清空名录的请求。非数组、缺少必要字段、无效状态或省略公开授权不能被当作已确认组织接受。

公开条目只输出 `id`、`name`、`participation`、`website`、`logoUrl`，以及为既有公开快照再次验证而保留的 `logoId`、`status:'confirmed'`、`publicConsent:true`。`logoUrl` 只由后台图片 ID 产生固定 `/api/public/portraits/<id>`；输入若包含此衍生字段，必须准确匹配，不能指定任意外部图片。内部备注和其他私有资料不进入公开内容。两种 store 重新启动后仍能验证及重读相同公开快照。

所有非空 logo 引用，包括未公开草稿，都在保存及发布前验证实际图片。匿名图片读取仅允许当前公开快照仍引用的组织图片；撤回或发布新名单后，不再凭旧引用读取。前台外链使用安全新窗口及不传 referrer，跨源图片读取不携带工作人员 Cookie。链接点击与实际参展／出席记录分别处理。

## 备份、恢复与回退

现有内容 journal、审计、权限、Origin／CSRF 和修订冲突机制继续适用，没有新增服务、IAM、DNS、trigger、环境变量或依赖。完整加密备份会沿每份历史草稿的 `logoId` 及历史公开 `logoUrl` 收齐组织图片；缺图或无效引用使备份失败，不静默遗漏。隔离恢复保留历史对象及图片，不激活旧名单、不恢复会话。

已有组织写入后，使用理解新字段的兼容版本修复。需要回退时先暂停编辑／发布、保存完整加密备份，再核对当前公开状态；不要用不了解该字段的旧版本重写整份内容，也不要用旧快照覆盖新资料。代码发布或读取旧快照不会替工作人员确认真实组织及授权。
