# 人员关系与共同名额：接续计划

用户已授权在志愿者完成实际发布后实施本阶段；本文件先记录契约，尚不代表功能已上线。随后还有新版邀请函与用户上传字体阶段，不能提前结束任务。[实施计划](implementation-plan.md)与[接续台账](session-recovery.md)保存当前状态。

## 确认参加接入 300 人

目前联系人实际回复与正式报名名额分开保存，导致只保存「确认参加」仍可能在报名页看到零。修复须在联系人云端保存得到有效回执后，才由服务器使用既有单人 `convertContacts` 和按 contactId 隔离的报名幂等来源，随后核对原报名关联及当前 admission。返回值保留联系人回执，并独立返回名额 confirmed、waitlisted、requiresReviewer 或 unavailable；转换回执本身不代表已确认名额。

自动接通只给具备邀约及审核能力的操作者；其他邀约同事可以保存真实回复，但清楚提示名额待有权限同事同步。联系人保存结果未知时不触发转换；名额写入未知时保留已保存回复并明确待核对，不盲重送、不当作零或成功。沿用既有共同上限／候补 CAS，正式统计只读 admissions.summary，不再加算联系人的 attending 数量。不自动寄信、不伪造网站隐私同意。

为既有已答应却尚未关联的对象提供明确核对／同步入口，复用已有预览／转换，每次最多 100 位、绑定名单修订；不在登入或 GET 时暗中补写。已关联报名重用原 ID；公开自行报名或另一 contact row 的人不能靠姓名／邮箱自动合并。回复后来变婉拒不暗中删除原报名或释放名额，提示进入既有明确撤回流程处理状态不一致。跨两份私有日志不是事务，来源被同事并行修改时应如实提示待核对，保留已写历史。

## 组织与人物关系

私有 `contact.operations.organizationMemberships` 采用最多 20 个明确 `{organizationId, role: 'lead'|'member', title:''}`；一人可关联多个已保存组织，不能从 profile.organization、公司名称或静态组织 fallback 猜测。旧记录省略视为无关联但不迁移写入，旧客户端省略则保留当前关系；明确空数组才解除当前关系，历史仍在。旧 migrationArchives 和联系人快照校验同步兼容，避免新增默认值导致原资料无法读取。

展位可增加可选 `organizationId`，保留原 organization 显示字串；旧字段省略与原 hash 不变，旧客户端省略保留，明确空字串才解除。组织退出或引用消失保留历史并标需核对，不因资料变化猜测新关系。成员关系不是现场职责，不自动成为讲者、占展位、确认名额或公开成员名单。

嘉宾／讲者继续用 `guest.contactId`，场次继续用 `session.guestId` 及联系人逐场职责。新增反向选择现有人員的入口，只有同时有活动编辑与邀约权限才维护私有人物关联；后端在查名单前校验。旧联系 ID 不因普通编辑或旧客户端保存而丢失，关联变更须重新核对公开授权。

## 总览与操作

人员页显示实际回复／邀请记录、已核对的正式名额、公开人物资料状态、组织成员关系及场次／展位，提供步骤指引与相应原操作入口。增加按明确组织 ID、嘉宾／讲者角色及公开状态筛选；现有负责人、跟进和安排筛选继续可用，简化不必要标签和重复大卡。

关系目录只读草稿／发布快照的最小关联元数据，literal outreach 授权在内容读取前完成，不回传无关人物简介、照片、联络方式或私有备注。个人工作页按当前人的已保存关系显示组织；组织编辑仅有 editor 时仍不读取私人名册，具备 outreach 才能查看最小成员列表与人员入口。关系源失败显示不可核对，并停用依赖否定事实的「未建立」筛选，不把失败当作无关联。

所有私人目录、成员／名额状态在退出、当前 401／403、换帐号及迟到回应时正确清除／隔离；编辑及同步有未保存保护，原件、历史、权限与既有 Excel 保留。公网投影不带成员关系、contactId 或私有组织备注。

沿用 Astro、Node24、香港 FC 与私有 OSS，没有新服务、IAM、DNS、费用、生产依赖或密钥。尽量复用现有联系人／转换／名额 journal，不新增人员副本或背景任务；新服务文件和静态资源必须纳入准确包闭包，完整备份与 EmailJS 原有设置保留。
