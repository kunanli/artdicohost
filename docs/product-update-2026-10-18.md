# 产品更新 — 活动直接报名与讲者、赞助招募

日期：2026-10-18（Asia/Taipei）。本文件记录用户在前端开发期间明确提出的新决定；保留原 10 份规范与 `docs/implementation-plan.md`，不覆盖历史文件。执行当前产品行为时，本文件下列决定优先于原规范中冲突的意向登记、邀请审核和讲者已确认暗示。

## 用户决定

1. 不再采用「参与意向登记 → 审核邀请 → 才能参会」流程。改为**活动报名**：正式系统对必需资料校验并成功持久化后即完成普通参会报名，不等待普通参会邀请或人员审核。页面标题、按钮、步骤和 FAQ 使用「活动报名 / 报名参加」，不再宣传邀请确认制。
2. 场次讲座的讲者尚未确定。保留暂定场次和时间，明确「讲者待定」；同时开放讲者招募与主题提案。讲者身份、讲题与场次安排须另行沟通，报名参会不等于获邀担任讲者。
3. 招募赞助方，设置独立入口与合作资料分支。可以沟通技术工具、物资、资金、导师及社群资源；当前没有已确认的赞助方、价格、等级或权益包，不虚构品牌、报价或曝光承诺。赞助咨询不构成承诺，也不影响普通参会报名。
4. **保留并明确收集已经是 GGJ 站点负责人的报名，以及有意成为 GGJ 站点的筹备资料。** SO、RO 和新站点分别提供原生多选身份卡，允许同时选择。已有负责人登记站点名称、城市、首次组织年份、当前 / 历史角色、经历和交流意愿；新站点登记城市、机构、场地准备、团队准备、2027 GGJ 计划与支持需求。仍合并为一份活动报名，不能因普通参会报名成功而自动认定官方 GGJ 站点资格或服务年资。

## 相互独立的处理结果

| 事项 | 规则 |
| --- | --- |
| 普通参会报名 | 正式资料校验和真实持久化成功即完成；不加邀请审核门槛 |
| 现有 / 新筹备 GGJ 站点资料 | 随活动报名收集；官方资格、年资核验遵循各自正式流程 |
| 讲者主题提案 | 单独沟通讲者资格、主题与场次；不阻塞普通参会报名 |
| 赞助 / 生态合作 | 单独洽谈形式与安排；不自动形成商业或赞助承诺 |
| 展位申请 | 名额、布展和安排另行确认；不阻塞普通参会报名 |
| 一晚住宿 | 单独申请和审核，暂定 12 月 5–6 日；报名成功不代表获房 |

后台后续设计应将「报名已保存」与咨询、合作、住宿结果分开。原 `new/in_review/awaiting_maria/approved/...` 候选状态不能再作为普通参会准入条件；Maria 审阅不作为所有参会者的报名门槛。与 Maria 分享资料仍须满足权限与隐私要求。

## 当前交付与真实报名的界限

当前仅开发桌面 / 手机前端体验版，生产提交保持关闭，没有真实 API、私有 OSS 写入或正式编号。表单本地校验完成只显示「演示完成，没有发送或保存资料」，不能假装报名成功。示例资料均为合成数据，不使用持久化存储或远端传送。

未来接入真实保存后才可显示「报名成功，可参加活动」与非连续编号；写入失败、断网或未知结果必须明确提示和可靠重试，不回退为假成功。后台独立鉴权、最小权限、隐私同意、保留期限、撤回 / 删除、幂等、备份恢复及上线授权要求继续有效。

日期、署名、交通细节、隐私处理者与联系方式等原有待确认事项仍待确认。本次没有自动创建云资源、购买服务、修改 DNS 或部署生产站点。

## 同日追加：工作人员安排场次与展位的本地后台

用户进一步明确需要工作人员后台，用于安排活动场次与出席展位。因此本阶段新增**仅用于本地验证的功能性内容后台**；上文「没有后台」的描述更新为「没有已部署的生产后台」。普通参会表单继续保持不提交真实资料的前端演示，不能将内容保存成功显示为参会报名成功。

- 后台界面本版维护场次和展位草稿；活动标题、日期、时区、场地与确认状态为只读。内容 API 对这些活动字段同样校验并按发布版同步，后续可增加对应编辑界面。场次包含稳定 ID、开始 / 结束时间、A/B/C 区、标题、讲者姓名、讲者确认状态、草稿 / 排定 / 取消状态和内部备注。展位包含稳定 ID、编号、机构、项目、C 区、待确认 / 已确认 / 取消状态和内部备注。
- 保留已公布规划的全部 15 个时间段，初始 A 区 15 场、B 区 13 场（略去「—」）、C 区 15 场。讲者初始全部待确认，无虚构姓名或参展机构；展位列表从空列表开始，由工作人员填写实际资料。
- 场次和展位各最多 200 条。时间必须为 HH:mm 且当日结束晚于开始；同区已排定场次不得时间重叠，可相邻或跨区并行。ID 在改名、排序和发布中保持稳定；展位编号忽略大小写去重。
- 保存草稿与明确发布是两步操作。草稿封装为 `{revision, content}`；公开版本为 `{revision, publishedAt, content}`，修订号和并发控制由本地 API 维护。界面与 API 鉴权、会话、CSRF、文件原子保存与备份由对应实现处理，schema 本身不授予权限。
- 发布前执行完整校验，再做严格公开白名单投影：隐藏草稿场次；待确认讲者姓名不公开；内部备注和未知联系字段不公开；展位只公开已经确认的编号、机构、项目与区域。工作人员的明确发布操作代表这些公开字段已获核准；不得把内部草稿 JSON 原样返回给公众。
- 取消场次保留公开的取消状态，供页面明确提示。未确认展位不进入公开名单；确认参展不等同于赞助合作，也不形成虚构赞助权益。日期和场地仍保留暂定标记，除非工作人员依据已确认事实更新。
- 后台采用本地文件保存，不接入真实报名名单；不因此创建云资源、修改 DNS 或上线生产。生产级 OSS/FC 存储、账号治理、审计和运维仍按后续阶段另行验证。
