## 数据与部署边界

| 模块 | 当前实现与限制 |
| --- | --- |
| 活动前台 | Astro 静态页面；普通报名表为明确标识的未提交演示，没有真实受理或正式编号 |
| 场次 / 展位后台 | 本地 Node API、独立账号、草稿 / 发布修订；仅监听本机地址 |
| 私密联系人 | 独立 `contacts.json`、`outreach` 权限、来源幂等、版本冲突检查、内部跟进与邀请记录 |
| 图片邀请函 | 浏览器生成 PNG；默认暂定；已生成不表示已发送或已回复 |
| Wallet / EmailJS | 接入准备与内容预览；账号、签名 / 服务配置和实际发送尚未完成 |
| 域名预览 | 独立静态托管产物；当前文档不证明已经部署、DNS 已生效或 HTTPS 已通过 |

原始工作簿、实际联系人、联系方式、私人邀请图片、账号环境文件及备份不进入 Git、CI 日志、静态产物或预览托管。导入仅由本机认证后台处理，公开内容投影不包含联系人或内部安排。上线静态页面不能代替真实报名持久化、生产鉴权、资料保留 / 删除或备份恢复验收。

## 后续接入顺序

先提供独立 OSS 静态桶的创建步骤；取得实际 bucket、地域与域名绑定信息后，再核对构建产物、部署版本、DNS 和 HTTPS。用户确认所需资源与配置后方可实施相应操作，本次文档不代表已创建或已上线。随后配置 Wallet / EmailJS，分别验证签名、收件内容和受控发送。真实报名及多人云端后台按原规范接入独立 FC 与私有 OSS，需完成其独立数据、安全与运维验证。

本地名单的权限、导入、备份、删除和恢复流程见 [私密意向名单说明](local-contacts.md)。本文件没有记录真实姓名、联系方式、工作簿内容或部署凭据，也不借用旧版本测试数字证明本次变更已通过。
