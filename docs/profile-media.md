# 人物资料、组织呈现与照片处理

2026-10-21。活动后台「讲者与嘉宾资料」保留一人一条稳定嘉宾记录，可以从已授权的私密人员名单准备草稿。公开职责、实际出席回复、报名名额及公开授权分别维护；名单角色调整不会自动公开人物或授予名额。

人物新增可选 `title`（200 字）、`bio`（4000 字）、`website`（500 字）及 `publicRoles`（`speaker`、`guest`、`organizer`、`moderator`，最多四种且不可重复）。旧记录未提供时不补空键，保持历史规范化内容及公开快照兼容。两个内容 store 都按稳定嘉宾 ID 保留旧客户端遗漏的新增字段；清空必须明确提交空字串或空数组，过期修订仍拒绝。

人物列表以「停止公开」取代删除，保留全部人物资料、照片引用及场次关联，只将确认状态和公开授权改回待确认／未授权。仍需保存草稿并发布才改变前台；角色或曝光调整不会删除报名原件、私密人员资料或人物简介。

只有已确认、明确公开授权且有有效头像者进入发布快照。前台按姓名、活动职责、职称与机构呈现，可展开简介、网站及真实已排场次；场次不从私人安排或原始意向推断。点击场次会切到对应区域并展开完整节目。网站仅接受不含帐号／密码的 HTTP／HTTPS；页面用文字节点输出资料，外部链接不传 referrer。更改姓名、机构、职称、简介、网站、职责或头像都会要求重新核对公开授权。

组织继续复用已确认展位，不建立重复组织名册。机构名、项目、展位位置、公开简介及可选网站层次显示，负责人和联系方式仍不公开。`booths[].website` 只在明确存在时存入／发布；旧客户端遗漏会保留当前值。

## 自动照片处理

照片与作品图先在当前浏览器处理，原件不上传。接受静态 JPEG、PNG、WebP，原件上限 12 MiB、四千万像素、单边 16384 像素。读取图片头后、实际 bitmap 解码前核对像素，拒绝动画 PNG／WebP、格式伪装、无效或过大的尺寸。浏览器解码时应用 EXIF 方向；不支持 ImageBitmap 时使用带清理的临时 Blob URL。

头像最长 800px，作品图最长 1600px，不放大小图。重新绘入白底 canvas，按固定且有界的质量／尺寸级别编码为 JPEG，最终须不超过 512 KiB。重新编码移除原始 EXIF／GPS 等元数据；界面显示原始与处理后尺寸、最终体积。处理取消、解码失败或上传回执不明都不显示上传完成。后台原有严格 JPEG／PNG／WebP 结构、像素、字节上限、规范化及雜湊校验保留。

照片上传与人物应用、草稿保存、公开发布各自独立。文件选择不会自动勾选公开同意；照片先保存在私有对象，只有明确发布后且仍被授权公开内容引用才可经公开图片接口读取。

## 回归与操作

三份新增 Node 测试覆盖：旧快照 shape、公开门槛／私密字段剔除、角色与网址校验、真实已排场次、两种 store 的旧 UI 漏栏保留／明确清空／修订冲突，以及解码前的大小／像素／动画／取消门禁。

`tests/browser/profile-media-smoke.mjs` 使用真实 Chromium 和完全拦截的合成 API：超大像素先拒绝、3200×2400 原图压至 800×600 且服务端可规范化、EXIF 方向 6 的像素及 fallback decoder、授权重新勾选、保存发布人物信息、组织网站、实际场次链接及 390px 布局。运行方式同[浏览器回归](../tests/browser/README.md)，把脚本路径替换为该文件。截图仅在忽略目录 `.local-data/browser-evidence/`，未使用真实人物照片或问卷。
