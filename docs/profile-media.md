# 人物资料、组织呈现与照片处理

本轮操作按[默认公开](default-public-visibility.md)与[统一保存](admin-save-workflow.md)更新，准确来源及实际部署状态见[本轮验收／发布记录](admin-save-visibility-release-2026-10-22.md)。旧版要求确认及授权才能公开的门槛已被新规则替代；相关资料／照片变更后的授权重核仍保留，但不阻挡公开。活动后台「讲者与嘉宾资料」保留一人一条稳定嘉宾记录，可以从已授权的私密人员名单准备草稿。公开职责、实际出席回复、报名名额、公开授权事实及公开开关分别维护；准备草稿或调整角色不会授予名额，也不会发布前台。

人物新增可选 `title`（200 字）、`bio`（4000 字）、`website`（500 字）及 `publicRoles`（`speaker`、`guest`、`organizer`、`moderator`，最多四种且不可重复）。旧记录未提供时不补空键，保持历史规范化内容及公开快照兼容。两个内容 store 都按稳定嘉宾 ID 保留旧客户端遗漏的新增字段；清空必须明确提交空字串或空数组，过期修订仍拒绝。

人物列表及编辑窗口使用「公开／未公开」开关，默认公开；明确切成「未公开」使用 `visibility:'private'`，保留全部人物资料、照片引用、场次关联、原确认及授权事实。列表开关直接云端保存，编辑窗开关随本表单「保存」提交；之后仍需明确「发布到前台」才撤下旧版。角色或曝光调整不会删除报名原件、私密人员资料或人物简介。

通过服务端字段与引用校验、未明确设为「未公开」的人物可进入新发布快照；资料确认、出席回复及授权不再阻挡公开，原事实不会改成已确认或已授权。头像和公开职责选填，缺头像以姓名首字显示，不请求空图片地址；非空图片引用仍须严格校验。前台按姓名、活动职责、职称与机构呈现，可展开简介、网站及真实已排场次，待确认等状态如实显示；场次不从私人安排或原始意向推断。点击场次会切到对应区域并展开完整节目。网站仅接受不含帐号／密码的 HTTP／HTTPS；页面用文字节点输出资料，外部链接不传 referrer。更改姓名、机构、职称、简介、网站、职责或头像仍会清除当前表单的旧公开同意勾选，提示重核这份资料的授权；旧历史保留，公开开关不会因此关闭，重核也不作为发布门槛。

独立的[参与组织名录](participating-organizations.md)用于组织图片、名称、对方页面及参展／一般参与身份；没有展位的组织也能列入。原展位资料继续维护机构名、项目、位置、公开简介及可选网站，负责人和联系方式仍不公开。`booths[].website` 只在明确存在时存入／发布；旧客户端遗漏会保留当前值。

## 自动照片处理

照片与作品图先在当前浏览器处理，原件不上传。接受静态 JPEG、PNG、WebP，原件上限 12 MiB、四千万像素、单边 16384 像素。读取图片头后、实际 bitmap 解码前核对像素，拒绝动画 PNG／WebP、格式伪装、无效或过大的尺寸。浏览器解码时应用 EXIF 方向；不支持 ImageBitmap 时使用带清理的临时 Blob URL。

嘉宾与组织支持[本地裁切、缩放、移动和去背](staff-image-editing.md)，输出最长 800px；实际透明度保留 PNG，不透明继续 JPEG，均有界压到 512 KiB。作品图继续使用最长 1600px、不放大小图及白底 JPEG 默认处理。重新编码移除原始 EXIF／GPS 等元数据；界面显示原始与处理后尺寸、最终体积。处理取消、解码失败或上传回执不明都不显示上传完成。后台原有严格 JPEG／PNG／WebP 结构、像素、字节上限、规范化及雜湊校验保留。

照片上传后，在人物编辑区直接按附近「保存」，本次云端回执核对成功才原位显示「已保存」并保留编辑对象；再按就近「发布到前台」或进入发布页明确发布，不再先应用再保存。常规本机暂存和已载入云端草稿固定浮窗不作为保存结果，恢复／冲突／未知提交时才显示工具。文件选择不改公开同意；照片先保存在私有对象，只有当前已发布公开快照仍引用的图片才可经公开图片接口读取。

## 回归与操作

本轮公开与保存结果见发布记录；`tests/default-public-visibility.test.mjs` 覆盖默认公开、明确未公开、事实保留及旧快照兼容。以下照片测试记录为历史验证范围，不用旧公开门槛代替本轮规则；资料变更后的授权重核与公开设置分别核对。

历史 Node 测试覆盖旧快照 shape、私密字段剔除、角色与网址校验、真实已排场次、两种 store 的旧 UI 漏栏保留／明确清空／修订冲突，以及解码前的大小／像素／动画／取消门禁。

`tests/browser/profile-media-smoke.mjs` 使用真实 Chromium 和完全拦截的合成 API：超大像素先拒绝、3200×2400 原图压至 800×600 且服务端可规范化、EXIF 方向 6 的像素及 fallback decoder、授权重新勾选、保存发布人物信息、组织网站、实际场次链接及 390px 布局。运行方式同[浏览器回归](../tests/browser/README.md)，把脚本路径替换为该文件。截图仅在忽略目录 `.local-data/browser-evidence/`，未使用真实人物照片或问卷。
