# 公开内容与游戏／作品操作

本说明对应开发中的公开可见性阶段，实际发布状态以[接续台账](session-recovery.md)为准；不因为存在本文件便视为已上线。

## 公开流程

1. 在嘉宾、组织或游戏与作品独立页修改，按本区块附近的「保存」。取得云端保存回执后才能继续发布。
2. 查看每条记录的公开状态。绿色「已公开」表示实际发布快照已有该记录；若同时显示「待更新」或「待撤下」，前台仍显示原版本。红色「未公开」表示实际快照没有该记录，旁边列出未确认、待授权、缺封面或未安排展示等原因。无法核对时显示中性状态，不能当作未公开或已公开。
3. 按原因进入对应编辑处。只有工作人员核实本人／组织授权后才勾选；查看提示不会代为勾选。嘉宾头像和公开职责可稍后补，姓名及机构等必需资料仍须完整。
4. 在「公开发布」页核对新增、更新、撤下与排除原因，再由有发布权限的工作人员明确发布。保存、切换页面、确认出席、生成邀请函都不会自动发布。
5. 公开页重新可见、返回页面或重新取得焦点时会重新核对发布内容。网络失败保留最后已核对版本并提示；要撤下全部内容，发布明确的空集合，不能用读取失败代替撤下。

「停止公开」只撤销公开授权，保留已确认事实、人物关联及历史；保存并再次发布后才从前台撤下。人物出席和公开状态互相独立，公开嘉宾不等于已确认出席。

## 游戏与作品

同一列表管理学生作品、独立游戏、团队作品。旧学生记录保留原ID及历史，显示为学生分类，不会因打开编辑器就改写旧资料。新作品选择分类，保存联系人、回复、材料和内部备注；私密资料不出现在前台。

作品可以明确选择创作者组织，以及已确认展位或已安排分享。一个展位可关联多件作品；创作者组织与占用展位组织可以不同，核对提醒不会强制改写关系。组织关联不等于公开组织授权，前台只显示同一已发布快照内已获授权的组织链接。

作品公开仍须核准、确认参加、作品公开授权、有效封面，并至少有一项有效展示安排。作品数量及填报成员数不等于实际去重参会人数，也不增加共同300名额。正式名额仍以报名与审核的容量记录为准。

## 人员与邀约

出席回复使用绿色「已确认出席」、红色「未确认出席」／「不出席」，同时保留文字。嘉宾资料确认不是出席回复。名额确认、出席回复及公开授权分别显示。

跟进人姓名使用固定彩色标签，同一名称在排序、筛选及刷新后保持一致；未指派使用灰色。颜色仅帮助辨识，不改变负责人的姓名、权限或联系记录，也不用红绿表达跟进人身份。

## 接续与回退

继续使用原`showcases[]`、schemaVersion1、storageVersion1和完整备份；新增own可选`kind`与`organizationId`，旧记录缺字段保持缺字段。两存储层兼容旧客户端漏传已保存的新字段，明确空字符串解除组织关联；已失效旧关系保留待核对，新增失效关系拒绝。未知回执原正文、稳定ID及本机草稿不会因显示默认分类而改变。

本阶段无新资源、账号、权限、依赖或秘密配置。恢复须采用理解这些可选字段的兼容写入版本；不要用旧完整内容快照覆盖之后的报名、联系及安排。代码回退与业务快照恢复分别操作，遵循[备份与恢复](maintenance-backup.md)及[部署](08-deployment.md)。

部署新增固定匿名`GET https://api.artdico.host/api/public/content`，带公开站Origin、无cookie／认证／跳转、限时限量；检查CORS及严格公开投影。日志只含发布版本、时间和各类数量；404明确记尚未发布，不声称资料已同步。测试不替真实人授权或发布真实草稿，不发送邮件。
