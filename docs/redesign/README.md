# ARTDiCO HOST 改版執行總覽

更新日期：2026-11-01（Asia/Taipei）。P1–P6 軟體已交付並實際發布，main `40ea32a6` 的 1535 項測試、兩種 ZIP 離線啟動、私有 OSS、13 個後台頁面及 51 個公開物件核驗均通過，見 [P6 最終紀錄](p6-release.md)。真實收件、入群、Wallet、同事觀察及真實資料核對維持獨立人工清單。

使用者已確認接續 UX 優化；[UX1](ux-clarity-release.md) 已由 PR #56 發布於 main `cc1281f8`，正式核驗 1536 項測試、13 個後台頁面與 51 個公開物件。[UX2 具名寄送與連續處理](ux-workflow-release.md) 由 PR #57 發布於 main `5ec45815`，PR／main CI 與實際 FC／OSS／HTTPS 均通過：1586 項測試、704 個來源檔、準確包離線啟動、私有 OSS、13 個後台頁面及 51 個公開物件。UX1、UX2 軟體已上線；四項真人與真實資料核對仍待人工記錄。

這次改版以「一人一個工作入口、多份來源保留、一個有效參會名額、一個私人參會頁」整合首頁、工作人員操作與參與者體驗。沿用現有 Astro、獨立香港 FC、公開靜態 OSS 與私有業務 OSS，不重建已完成的報名、名額、通知與人員關聯系統。

後台以簡約、直覺、少字為驗收要求。預設只突出人員、當前狀態與一個下一步，流程為「找人 → 核對 → 處理」；長說明留在操作手冊，原問卷、來源、歷史與進階設定按需展開。簡化呈現不合併出席、名額、通知及公開的真實狀態。

## 已確認的產品決策

| 項目 | 本輪實作方向 |
| --- | --- |
| 首頁 | 以 FrontEnd_Resource 黑底、紫橙星球設計為視覺方向，一頁式、微信手機瀏覽優先；正文使用 HTML，重要資訊不依賴動畫 |
| 展位 | 可依需要新增，不宣傳固定格數；調整後台位置限制，保留唯一編號、位置衝突與一般技術資料量限制 |
| 嘉賓 | 首頁嘉賓區只列實際確認出席者，並保留講者、主持人、嘉賓等角色差異；資料確認、出席回覆、正式名額與公開設定分開 |
| 作品 | 新建與重新歸類只提供「學生作品」「獨立遊戲」；舊 team 記錄及已發布快照仍能讀取，不自動將所有團隊作品改成獨立遊戲 |
| 申請入口 | 保留一般參會及同一申請內的演講提案，移除公開展位申請與送作品申請入口；保留已安排作品與展位導覽 |
| 住宿 | 只在 Q&A 說明少量外地支持與聯絡信箱，不新增公開住宿表單；舊問卷已有需求仍留在跟進清單 |
| 舊意向 | 保留原問卷、來源、同意與歷史；已有人員沿用主記錄，不要求重填，不靠姓名或信箱自動合併 |
| 參與者服務 | 私人參會頁統一呈現最新名額、日期地點、群碼、Wallet 及保存方式；待審、候補、拒絕、取消不提供群碼或 Wallet |
| Email | 沿用有效 EmailJS 設定；新增申請回執與行前提醒時使用獨立通知種類，不挪用正式確認信的寄送身份 |
| Wallet | 保留既有簽章設定，以 iPhone 真機驗收完成可用性核對；不以下載成功表示已加入裝置 |
| 微信群 | 由指定同事維護有效群碼；網站顯示入口不等於已入群，取消參會後群內處理由管理員另行完成 |

本輪首頁黑底紫橙方向及住宿簡化，承接本次對話，取代 AGENTS.md 第 7、8 條中與本輪衝突的舊展示／公開表單要求；其他資料、權限、稽核及安全要求繼續適用。既有住宿資料不刪除。

網站維持簡體中文。住宿 Q&A 使用：

> **外地来宾有住宿支持吗？**
>
> 本次活动提供少量外地来宾住宿支持。有需要的朋友，欢迎提前通过 support@artdico.co 联系主办方了解安排；名额有限，住宿安排将另行确认。

信箱須可點擊及複製，與公開聯絡設定保持一致。

## 分階段交付

| 階段 | 工作 | 完成後才能進行 |
| --- | --- | --- |
| P0 | 基準核對、決策與步驟文檔 | P1 資料契約設計及合成實作 |
| P1 | 舊資料相容、兩類作品、展位擴充、出席公開規則、多人場次與活動資訊一致性 | P2 使用新契約整合工作頁 |
| P2 | 單人工作入口、舊意向分流、主記錄及明確下一步 | P3 參與者服務整合 |
| P3 | 私人參會頁重排、群碼失效處理、Wallet 與保存備援 | P4 完整通知體驗 |
| P4 | 申請回執、正式確認、行前提醒與寄送異常工作流 | P5 全頁視覺與動效整合 |
| P5 | 新首頁、素材優化、雙星球、嘉賓卡、作品輪播、日程、聊天 Q&A 與分享資訊 | P6 最終整合驗收與發布 |
| P6 | 相容性、手機／微信／iPhone、部署包與正式發布核驗 | 本階段完成與後續日常營運 |

P1 至 P5 可各自拆成小 PR，依相容順序交付；P6 是完整流程的最後驗收，不取代各階段自己的檢查。合成首頁版型可提早準備，但正式整合須依 P1 契約。

這些是倉庫內可閱讀並執行的本地技能，沒有新外部服務。會話是否自動載入以當次可用技能清單為準；即使清單尚未更新，也可先讀 SKILL.md 並按其中命令操作。不要把建立技能檔案當作已通過全部旅程。

P2 的智能輔助優先使用既有進度規則，顯示建議動作、原因、阻塞事項及已保存來源修訂，並提供唯讀異常清單。原問卷摘要與回覆草擬如日後加入 AI，須保留來源與待核對處，不讓草稿代替核准、合併、寄信或發布。

## 既有能力與新增範圍

已具備：正式申請與私人查詢頁、審核／候補／共同名額、穩定來源關聯、人工重複核對與主報名、逐人通知及未知結果保護、內容草稿／發布、圖片處理、群碼維護、Wallet 簽章與下載。

本輪補齊：工作入口集中、出席證明的安全公開表示、兩類作品與動態展位、多人公開場次、已核實活動資訊的一致來源、私人頁操作層次、群碼缺失提示、新回執／提醒、新首頁及素材發布相容。

不在本輪直接擴充：會員系統、公開自行修改全部資料、參與者自行點選 RSVP、QR 到場簽到／防重複入場、Wallet APNs 推送、支付、新資料庫或新雲資源。現階段以工作人員保存真實出席回覆、現場按姓名／編號核對；後續有需要再獨立設計。
