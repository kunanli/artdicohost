## 嘉賓為何只有三位

正式 R44 公開快照有9筆嘉賓資料，但 `guestAttendance.confirmedGuestIds` 有3個ID。`shared/guest-display.mjs` 的 `publicGuestCards` 對合法明確出席證明取交集，因此首頁與公開預覽皆只有3張；手機沒有另外截斷人數。後台列表只按公開陣列判定「已發布」，因此可能同時標示9人已發布。R43缺少根出席證明時則走相容分支，保留9張而不捏造出席。

伺服器證明由明確人員關聯與有效聯絡人的真實回覆產生，不由綠色公開開關、照片、名額或資料confirmed產生。僅憑公開快照，無法斷言另外六人是尚未回覆、未關聯或其他原因；不能為顯示卡片而批次改為出席。

建議產品規則：首頁按「公開」開關展示全部合法嘉賓，出席證明只保留獨立真實狀態；標題改為「嘉宾阵容」，避免把公開資料說成確認出席。明確private仍不可見；錯誤、重複或未知ID證明仍拒絕，不移除安全校驗或補假confirmed。首頁、預覽與列表共用同一集合。

使用者已選定：依後台「公開」開關展示全部嘉賓，出席確認另外保留。依此更新P1b展示契約；不修改公開證明或真人回覆來湊人數。
