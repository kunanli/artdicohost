# 活動行報名與 Apple Wallet 接續

2026-11-02。這是接續實作與操作方案，**不表示活動行已接通、網站審核設定已更改或官方徽章已換上**。使用者確認活動行為「免費、報名即確認」，並希望一般參會省去審核；採以下方向接續，既有名額、確認信、私人頁、群碼及簽章功能重用。

## Apple Wallet 圖標怎麼用

圖標放在「已確認名額」的本人私人參會頁，點擊沿用現有簽章 `.pkpass` 下載；不用重新申請 Apple 憑證或開發 App。參與者由確認信開啟私人頁，在 iPhone Safari 點「加入 Apple Wallet」，再按系統提示添加。微信內先按頁上指引複製私人連結到 Safari；Android 保留下載／保存方式。候補、既有待審或撤回不提供有效 Wallet 下載。活動行已出票的參與者同步至統一名額後，無需接受第二次參會審核。

1. 主辦方從 [Apple 官方徽章指南](https://developer.apple.com/wallet/add-to-apple-wallet-guidelines/) 的 Download badge files 取得官方 SVG。下載頁要求本人同意 Wallet Marketing Agreement，開發者不代勾；本次未取得該檔案。
2. 取得原檔後，由開發者以本地資產加入私人頁按鈕，保留整體比例及至少高度0.1倍留白，不重畫、裁切、變色、加陰影／動畫或用網站預覽圖代替提供的徽章檔。
3. 按鈕保留44px以上可點範圍；只有可直接添加的 Safari 狀態顯示徽章，微信指引、桌面下載、準備中及失敗狀態使用清楚文字。圖片與文字需分開綁定，避免現有 `textContent` 更新清掉徽章。
4. 使用既有合成私人頁瀏覽器案例核對裝置、下載、圖檔解碼、鍵盤及撤回清理，再經正常發布。真 iPhone 添加另記，下載成功不表示已加入裝置。

目前保留可用的文字入口，不上線缺失圖片。實作位置：`src/pages/registration/confirmation.astro`、`src/scripts/confirmation.mjs`、`src/styles/confirmation.css`；簽章與後端無需因換圖調整。憑證現況以 [最新 Wallet 紀錄](../apple-wallet-setup.md) 為準，不重做較早的開戶步驟。

## 活動行怎麼併入現有流程

使用者指定：[活動行報名頁](https://9525102647817.huodongxing.com/event/8884819113200)，並明確回覆「免費，報名即確認」。公開頁在本次讀取環境被 CONNECT 403 阻擋，搜尋索引也無結果，因此具體票種、名額上限、取消及同意文字仍未讀到；沒有登入、抓取私有 API 或繞過限制。

建議第一版：

**活動行報名即確認 → 同步名單、核對重複 → 寄送參會指南 → 本人私人頁 → 微信群／Wallet。**

在活動行已填過的人不再重填本站申請。轉接器就緒後，可將網站主要報名入口指向活動行，網站保留活動介紹、統一後台及參會服務。現階段不先切換入口，避免收到資料後無法接續。

一般參會不設第二次人工審核；演講提案、住宿及特別安排獨立確認，不影響普通入場。活動行可報名額須先扣除已確認嘉賓、工作人員及其他有效來源的預留，共用同一活動總容量；額滿停止或候補。同步已出票來源若遇容量／重複票衝突列為工作人員待核對，不偷偷把已確認者改成候補。活動行票碼不能直接視為本站 Wallet QR，也不保證其核銷器能掃本站票券。

| 工作 | 現有能力 | 還需要補 |
| --- | --- | --- |
| 收資料 | 已有私密匯入、預覽與來源追蹤 | 活動行匯出欄位轉接；現在的Excel入口固定原問卷，不能直接讀活動行表格 |
| 核對人員 | 已有重複線索、人工合併、主報名與共同名額 | 活動行來源標記及穩定每人／票ID；多人訂單須分人，不能用行號或姓名當來源ID |
| 重複匯入 | 相同來源／內容略過，來源變更拒絕覆寫 | 「有變更／已取消待核對」，保留人工更正，不假設雙向同步 |
| 確認與通知 | 已有確認／候補、一次正式確認信與私人頁 | 將活動行有效出票作外部確認依據，完成去重與名額回執後提供私人頁，不加第二次審核；聯絡許可及通知結果獨立保留 |

後台只需「同步名單」及「發送參會指南」兩個日常動作。同步先看新增／已存在／待核對／已取消，再明確執行；只處理例外，不逐人再審核。主列表仍只突出人員、狀態及一個下一步，原答案／來源／歷史收合。現有單純匯入聯絡人不會自動建立名額；轉接器需接續既有明確來源確認與持久化回執，不把聯絡人匯入成功當成出票完成。

既有來源以 `sourceKey + sourceRowId` 去重；活動行應使用本站專用活動來源，例如 `hdx-8884819113200`，原始狀態、更新時間與授權依據放有界私密來源紀錄，不塞進舊問卷意向或長備註。平台同意不偽造為本站勾選；只有可證明且允許本活動聯絡的依據才進入既有確認信流程。

取消先列「待核對取消」：確認是否為目前主名額、是否另有有效來源後，再明確撤回。取消一張重複票不能自動取消另一份主報名；名額釋放、退款、通知及群內處理各自核對。

## 接下來的實作順序

1. 依已確認的免費即出票方向，核對活動行總名額、預留席位、取消設定及實際資料用途／聯絡同意文字。
2. 取得匯出表頭及兩三筆完全匿名範例，確認每人穩定ID、時間、狀態與多人票結構；不使用真名單作測試。
3. 實作小型活動行轉接器、差異預覽及私密來源紀錄；重用人員核對、名額與寄信，不建第二個後台。
4. 合成驗證重匯、多人訂單、同信箱不同人、來源變更、重複票取消、最後一席／候補及未知匯入／寄送回執；通過後才由主辦方明確匯入正式資料。
5. 最後調整網站報名入口與活動行完成頁說明；即時 API／webhook 待確認官方能力後再接同一轉接器，不先承諾自動同步。
