# 活動行主報名與 Apple Wallet 執行路徑

## 2026-11-26 正式執行路徑

在官網點選報名後，到活動行完成正式報名並取得原電子票。現場由活動行驗票及簽到。舊本站的入場短連結和簽到頁顯示活動行指引。符合路徑格式的舊短連結解析與簽到 API 回覆 `410 ENTRY_RETIRED`，有效的一般參會確認連結回覆 `410 REGISTRATION_EXTERNAL`。已存的站內名額和人員資料仍可由授權後台查閱。 [活動行活動頁](https://9525102647817.huodongxing.com/event/8884819113200) · [正式路由](../../functions/cloud-content/runtime.mjs) · [舊票券回覆](../../functions/entry-ticket/handler.mjs)

授權同事可在後台預覽及提交活動行名冊匯入，核對有效票、取消及重複來源。匯入維護票券來源與內部人員關聯，正式入場資格仍以活動行票券為準。公開網站另提供紀念卡申請，申請人填寫活動行報名編號與卡面資料。一般網站報名和講者申請已關閉。 [名冊匯入契約](../../functions/intent-invitations/import-handler.mjs) · [紀念卡表單](../../src/components/WalletApplication.astro)

## 紀念卡核准、領取與收藏

1. 工作人員至 [後台紀念卡](https://api.artdico.host/admin/cards/) 核對活動行報名及卡面身分。核准以主記錄、原申請、操作者及原操作識別寫入獨立管理日誌。核准和移除共用修訂檢查，重查同一核准操作可讀取原結果。核准只影響紀念卡資格，網站歷史名額帳維持原狀。 [紀念卡服務](../../functions/registration-confirmation/service.mjs) · [管理日誌](../../functions/registration-confirmation/repository.mjs)
2. 合併記錄由人員主記錄承接卡面及寄送。工作人員保存的 GGJ 站點／社群、參與經歷和可選卡面資料優先，明確清空也保留。其餘資料沿用仍與主記錄關聯的核准申請，或主記錄本身的紀念卡申請。若主記錄是一般舊報名且缺少指定來源，只採用一致的關聯紀念卡資料。英文郵件、JPEG 和 Wallet 共用身分格式。 [GGJ 資料選擇](../../functions/registration-confirmation/service.mjs) · [雙語身分格式](../../shared/general-application.mjs)
3. 具權限同事明確寄送後，申請人可用同一私人頁下載 JPEG，並在符合資格、簽章就緒的 iPhone 上加入 Apple Wallet。兩種卡供長期收藏，現場請出示活動行原電子票。核准和改卡面資料各自保存，寄送由獨立操作啟動。服務商接受、信箱送達及開啟是不同結果。上次寄送待核對時可先查原紀錄，明確重寄可能收到多封。 [郵件與寄送狀態](../registration-confirmation.md) · [領取頁](../../src/pages/registration/confirmation.astro)
4. 私人連結以限時 `receiptToken` 領取，預設有效至活動日結束後 90 天。系統核對公開站來源、主記錄、核准、活動資料及當前權限。Wallet 於簽章後再次核對。JPEG 可下載保存，Wallet 紀念卡的票面沒有活動日到期設定。移除後舊線上領取連結失效，已收藏檔案保留原版。新版可在原連結有效時重新領取。 [領取憑據](../../functions/registration-confirmation/tokens.mjs) · [簽章驗證](../../functions/apple-wallet/service.mjs)

正式發佈已核對準確提交 `ebed563a1ebdeb451f910db3aa78a51adf566fb5` 的香港 FC 與公開 OSS，公開 API 讀取活動修訂 130。匿名檢查確認講者已關閉、紀念卡開放及申請預檢可用。郵件與 Wallet 的配置就緒，真人收件和 iPhone 加入仍需各自核對。 [PR #116](https://github.com/kunanli/artdicohost/pull/116) · [正式發布 45776935655](https://github.com/kunanli/artdicohost/actions/runs/45776935655) · [資料與 API](../06-architecture-data.md)

> 2026-11-02最新決策：使用者明確選擇直接在本站填表、自動取得入場券，取代本文早先「活動行唯一一般報名」規劃。[本輪實作與回執](onsite-auto-registration-release.md)為目前入口依據；本文保留活動行與Wallet的歷史整合資訊，不授權修改外部頁面或自動匯入既有名單。

2026-11-02。使用者已以方案截圖確認帳號為「認證版」，包含名單批次匯入／匯出，活動為免費、報名即確認。採活動行為一般參會唯一正式入口，本站承接人員整合與參會服務。這份路徑規劃不代表活動行轉接器、入口切換或正式名單同步已完成。

### 參與者只走一條路

**官網 → 活動行報名即確認 → 收到參會指南 → 本人私人頁 → 微信群／Wallet。**

1. 官網的「立即報名」指向 [這個活動行頁面](https://9525102647817.huodongxing.com/event/8884819113200)，不再同時提供第二份一般參會表單。演講提案、住宿及特別安排獨立處理，不影響普通入場資格。實際入口須等名單轉接就緒後才切換。
2. 活動行表單保留必填的姓名與Email，平台本身需要的手機照用；機構、城市等選填，不要求重填已取得資料。Email用來寄私人參會頁與行前資訊，資料用途與聯絡告知須清楚。
3. 報名成功即有活動行確認資格，不再逐人審核。完成頁建議說明：「报名成功！电子票用于现场入场，参会指南及微信群／Wallet入口将另以邮件发送，请留意报名邮箱。」首版為批次同步，不承諾即時收到本站郵件。
4. 郵件只放本人私人參會頁；群碼在頁上讀取最新有效版本，不把容易過期的靜態群碼附在郵件。Safari可添加Wallet；微信內依現有指引在Safari開啟；不使用Wallet的人仍用活動行電子票。

### 主辦方日常只有兩個動作

- **同步名單：** 從活動行匯出，本站選檔後先看新增／已存在／需核對／已取消，再確認同步。相同來源重匯略過，只處理例外，不做第二次參會審核。
- **發送參會指南：** 對已同步且取得同一份有效名額、聯絡依據完整的人，明確發送一次；已發／結果待核對者不因重匯再寄。

首版可在固定時段批次同步，活動前另做一次取消與名額對帳；不需要為此購買即時API。實際頻率由主辦方依報名量安排，完成頁和郵件不寫不存在的即時服務。

### 名額、取消與舊名單

- 先整理既有已確認者、嘉賓／工作人員及其他預留，再設定活動行可報餘量，整場只算一份共同容量。新增受邀者需同步調整餘量，不讓兩邊各自承諾名額。
- 活動行每位參加人／票的穩定ID與本站主記錄關聯；多人訂單須分人。Email／姓名只作查重線索，不自動合併不同的人。
- 已在活動行報名的人不重填；既有受邀或舊問卷人員也保留原主記錄與歷史。若要在活動行統一出票，由主辦方批次補入並回連原人，不新增第二席。
- 取消先列例外，核對是否為有效主票、是否另有其他來源後才撤回；取消一張重複票不能撤銷另一份有效名額。第一版不承諾雙向即時取消同步。
- 平台出票、資料使用依據、本人出席回覆及本站公開設定分開保留；不偽造本站隱私勾選。缺Email、來源變更或容量衝突用一個「需核對」入口處理，不暗改已確認者為候補。

### 現場只用一套核銷

**目前建議活動行電子票／管家作唯一核銷來源。**

本站現有Wallet產生的是本站資格驗證QR，尚未共用活動行的票碼，也沒有到場紀錄或防重複簽到服務；換上官方徽章不會讓兩套QR互通。活動行新來源的Wallet應明確作資訊保存／私人頁入口，或在取得官方可用的原票碼後，才新增復用同一張活動行票的模式。未完成前，不向參與者宣稱Wallet可直接交活動行驗票。

### 開發接續與完成條件

1. 取得活動行匯出表頭和兩三筆完全匿名的有效／取消／多人票範例，確認穩定每人ID、狀態及時間；不使用真名單作測試。認證版已確認，不再重問是否購買方案。
2. 補活動行薄轉接器與差異預覽。現有Excel入口固定舊問卷，通用後端來源能力不等於已能直接讀活動行表格；單純建立聯絡人也不等於已同步有效名額。
3. 沿既有來源確認、主名額與通知，保留舊pending／rejected及原鍵／未知回執；不必先把本站所有公開申請改成免審。外部已出票只做技術對帳，不加第二次資格審核。
4. 驗重匯、多人訂單、同信箱不同人、取消重複票、來源變更、最後一席／候補與未知匯入／寄信；保留伺服器權限及既有128檔／40資產邊界。
5. 對接通過後，再切官網主要報名連結、收起第二個一般報名入口、更新活動行完成頁說明；真名單匯入與寄信仍由主辦方明確執行。

目前沒有登入或修改活動行、匯入真實資料、寄信、改正式名額或切換官網報名入口。認證版匯出權益已由使用者方案截圖與 [官方方案](https://www.huodongxing.com/price)核對；活動頁本身在本次環境仍讀取受限，其他欄位不猜測。既有簽章現況見 [Wallet設定](../apple-wallet-setup.md)，既有人員／來源契約見 [人員整合](../unified-people-workspace.md)。
