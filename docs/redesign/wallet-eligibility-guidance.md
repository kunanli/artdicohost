# 紀念卡資格提示一致性

2026-11-10，從已部署PR89／main b1493283接續使用者「繼續」的前後端體檢。新wallet-v1申請即使已有名額，卡面入場身分仍須由工作人員設定。私人API原先已回WALLET_IDENTITY_PENDING，但Email只看全站簽章就緒，因此仍有Wallet徽章／添加指引；前端又丟棄原因，只顯示泛用未就緒。以合成申請重現後修正，沒有操作正式名單或實寄。

Email仍送出已確認名額與私人連結，新紀念卡只有本人可信身分與簽章均就緒才附Wallet徽章及添加指引。中文確認信與英文確認／提醒正文同步處理；舊版一般申請的原指引維持。私人頁只保留明確允許的身分待確認原因，不轉送未知診斷字串；即使有名額，也不顯示票券下載。後台取得私人頁改用「查看当前可用的参会凭证」，不由名額直接推定Wallet可用。

身分設定、名額、通知仍分開。補上身分後重讀原私人連結會核對當前資格；已接受的確認信不因設定、刷新或部署補寄。舊通知身份、attempt／operation、未知回執、原始問卷及審計不變。首輪完整回歸找出舊合成provider以原Wallet文字識別正式通知，因改動一般申請指引而等待；收斂修正至新紀念卡後，重跑相關回歸，沒有更改舊錯誤／未知操作斷言。瀏覽器另修正先等待實際PATCH與saved回執再離頁，不能把保存時的disabled當已保存。
