# 报名审核与私人票券入口

2026-10-30。本阶段从 main `6984f82` 接续；发布及真实 HTTPS 结果在完成后补充，开发验证不等于已经上线。所有验证使用合成资料，不读取 Excel 原件、不提交正式报名、不寄真实邮件。

## 日常操作

`/admin/registrations/` 主列表只显示姓名／机构、参会状态、报名来源及操作。页首统计来自真实名额服务；内部核查的「新报名」不再与「已确认名额」并排显示。查找保留姓名、机构、编号及身份，城市／内部跟进／住宿等收在更多筛选内。

打开单笔「查看与核查」后，先看当前参会状态和基本资料。待审核才显示批准／不通过操作；已确认不再显示无效审批按钮。原始问卷、内部跟进、住宿及 Maria 人工记录分别收合，所有字段、原始来源、历史与独立保存契约继续保留。保存内部记录后保持当前编辑区打开；内部意见不批准申请、不授予名额。

名额、候补、受托登记、团队以及导出仍可在收合工具内使用，没有删减数据或按姓名合并人员。列表与详情读取不发送邮件，不自动批准、补位或创建报名。

## 私人确认页与 Wallet

已确认名额的记录可点击「取得私人确认页」，再打开或复制链接供本人／明确授权的人员在 iPhone Safari 中添加 Wallet。公开申请、Excel 意向转换及受托登记沿用各自不可变来源，不必重新提交另一份公开申请，也不会伪造网站隐私同意。人员本人不在名单时，不能拿其他人的记录当本人票券；原未知申请须沿用原提交核对。

新只读接口为 `GET /api/admin/registration-confirmation/link/<registrationId>`。准确后台来源、已认证 reviewer／superadmin 在数据读取前校验；不允许查询参数、其他方法或外站 CORS。仅明确选中的 confirmed 记录返回既有用途隔离确认 capability，签发前后均读当前资格；其他状态不返回链接。读取不创建报名、改名额、写通知或调用寄件服务。响应 private/no-store/no-referrer；能力令牌不能进入列表、普通日志、IndexedDB、工作簿或永久设置。

更换人员、关闭详情或会话失效立即清除链接、复制备用框和私密摘要；迟到回应不能重新显示旧人的链接。确认页、Wallet 下载及二维码继续重新校验当前名额，撤回后不再允许新下载。工作人员来源不显示虚假的待寄自动邮件，仍不自动获得仅公开申请提供的个人邀请 PNG。

## 未知申请恢复与诊断

已有 pending_submission 时显示精简核对卡，隐藏已锁定的长表单，原字段与主动同意的原正文保留。明确重试使用同一个幂等键和正文，不自动 POST、不清空草稿或换人重建。错误分清读取设置、提交验证或回执核对，以及网络、超时、HTTP 状态或响应格式；不回显提供者正文或秘密。仅改善可诊断性，未经证据不把真实网络故障宣称为已经修复。

`node scripts/verify-public-registration.mjs` 仅做一个匿名配置 GET 和两个 OPTIONS（验证与提交的浏览器预检），没有申请写入或 token 签发。CI 在部署前观察、实际部署后校验，输出仅固定阶段／状态／公开活动 ID。此检查不能替代用户所在网络的实际恢复请求。
