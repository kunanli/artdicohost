# 设置页保存与微信群期限

准确验收与实际发布状态见[本轮发布记录](admin-save-visibility-release-2026-10-22.md)。

本次调整对应设置独立页 `/admin/settings/{delivery,group,accounts}/`。每份设置表单只有一个主要「保存」按钮，状态放在按钮附近：修改后「未保存」、提交中「保存中…」、实际回执通过核对后「已保存」。读取状态、恢复本机草稿或生成账号密码都不是保存成功。工作人员邀请页是工作入口，没有可保存的设置，不增加无效保存按钮。

微信群替换的文件格式／大小和到期时间在字段旁显示错误，填写及已选原图在拒绝后保留。到期范围按服务器返回的 `serverTime`／`maxExpiresAt` 和浏览器单调经过时间计算；北京时间 UTC+8 输入保留到分钟，提供 1／3／7 天快捷值。七天是从当前时刻起算，不能任意延长到第七天 23:59；服务器原七天上限不变。初始快捷值仍须按二维码真实有效期核对，不会自动上传或延长旧二维码。

「已保存」须核对本次实际请求。群码回执验证版本、到期时间、类型及原始选档 `sourceSha256`；此摘要只在实际替换回执返回，不写入群码记录，也不在后续状态读取中冒充写入证明。邮件设置回执以同一 `operationId`、所选 `enabled` 和递增版本核对；若随后有其他修改，明确提示当前设置已变化。账号沿用原目录与原请求的完整回执核对，保存后保留该账号的编辑资料并清空密码；「新增账号」才清空表单。密码不写本机草稿，只有已确认的保存才提供本页交付资料。

响应丢失或回执无法核对时显示「保存结果待核对」，原请求不换编号盲目重送。邮件设置继续核对同一操作；群码和账号沿用人工核对与解除锁定流程。刷新不能证明密码或图片替换成功。本机普通自动暂存不再显示为主要保存提示，恢复、冲突及待核对入口保留。

本次没有新资源、凭证、依赖或持久化版本变更。API 新增字段向旧客户端兼容；新版前端要求同次后端的安全回执字段，须按既有完整发布流程一起上线。代码回退不恢复旧业务快照，完整备份及隔离恢复沿用 [维护流程](maintenance-backup.md)。测试均使用隔离合成数据，不上传真实二维码、不改正式账号、不实寄邮件。
