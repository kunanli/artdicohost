# 志愿者与分工

本轮开发分支 `feat/volunteer-operations`，以已上线 main `ddf7a2ea0b9c81d9222aefbef3e5155d7432b8a4` 接续。下述为本轮实现与验收范围；实际发布以[接续台账](session-recovery.md)最新证据为准，不能把候选功能当成已上线。

## 人员与名额

志愿者不是新建一份个人档案。在已有联系人或已保存报名中选择本人，记录稳定来源 ID；姓名、组织及必要联络资料读取原档，不以同名／相同邮箱自动合并。联系人明确转换的报名只认既有转换记录和 provenance；发生不一致时提示核对，不猜测关联。

「志愿者已答应」是志愿协作回复；「已确认参会名额」是现有 300 人共同名额；「已确认班次」是具体分工。三者分别保存，加入志愿者名单不自动报名、不变更工作人员类别、不发送邀请、不公开人物。

同一人跨多个班次，总人数只算一人。班次需求及缺额使用「人次」，避免把两班需求相加误报为不同人数。未确认名额、婉拒／退出、来源无法核对或安排失效时，不算已确认覆盖。

## 日常步骤

1. 从现有人員／报名挑选本人加入名单，核对真实联络许可与当前状态。
2. 记录负责同事、联系日期、下次跟进和志愿协作回复，填写本人可服务时段。
3. 建立岗位、区域／地点与负责人，再建立各岗位的班次及需求人次；可明确关联已存在的活动场次或展位。
4. 先提案，核对时段与本人答复、正式名额后再确认逐班安排。重叠时段、超出可服务时间及超过班次需求由后端拒绝；相邻班次端点可以相接。
5. 看覆盖／缺额与待核对问题，按需调整。取消／停用保留旧记录，实际回复和名额改变导致的旧安排问题应处理，不用删除历史来抹平统计。

所有表单明确保存后才写入云端。未保存输入保护关闭、退出和离页；未知回执保留原 operationId 与原内容，使用原操作明确重试，不自动发送新操作、改写他人版本或发布到前台。

## 权限与导出

入口 `/admin/volunteers/`，superadmin 或同时具备 outreach＋reviewer 的账号可使用；服务端在读取来源前授权。单独活动编辑、邀约或审核权限不取得整个志愿者名册。个人工作页同样按权限显示最小志愿状态／班次，其他角色不读取新日志。

Excel 提供名单、岗位／班次与分工／缺额的已保存快照，默认不含联络字段；确有需要才明确包含。导出范围、修订与摘要留私有审计，不生成公开链接，不自动转发给其他人。数据源不可核对时不把缺少的统计当成零。

## 开发与接续

复用既有 Astro、Node24、FC 和私有 OSS。新日志为 `cms/v1/volunteers/<eventId>`，使用内容定址不可变快照、条件追加与严格回执，纳入完整历史备份及隔离恢复。日志／审计达到上限停止新写入，不清空或截断。没有新增云资源、IAM、DNS、费用、生产依赖或凭证。

测试仅使用合成资料，覆盖权限、重复来源、确认状态、半开时间冲突、可服务时段、超需／缺额、人次与人数、CAS／未知回执／重启、Excel与加密备份、手机与会话隔离。最终按现有准确 PR／main 工作流核对真实私有 OSS、300 人政策和公开 HTTPS；真实名单、照片与邮件不用作夹具。

回退只用兼容现有志愿者日志的代码，保留全部新日志与业务审计；先保护私有备份，不用旧快照覆盖后续安排。EmailJS 和 Wallet 配置仍独立保留；本模块没有新增实际寄送或票券操作。
